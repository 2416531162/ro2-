# 欧艾迪单路驱动器 ×2（Gen5 差速底盘）

Gen5 的左、右两个后轮毂电机各接一台欧艾迪智能 FOC 单路驱动器。每台走 CAN 或 RS485，由 `oid.yaml` 的 `left_bus` / `right_bus` 选。

**本车（2026-09-29）：左轮 RS485、右轮 CAN。**两条总线由 `SplitLink` 拼成一条链路，轮速换算、里程计、心跳、故障停车、控制权仲裁都与两台都走 CAN 时相同。

协议依据：

- CAN：厂家《智能 FOC 无刷电机驱动器（CAN 系列）编程手册 V1.2》（单路）。它与《双驱 CAN 系列》V2.0 的指令、查询、心跳和示例报文逐条对过，内容相同；双驱版只是多了一节共享 ID。编解码按手册示例报文逐字节核对，见 `tests/test_oid_driver.py`。
- RS485：厂家《智能 FOC 无刷电机驱动器（RS485 系列）编程手册 V1.3》，Modbus RTU。手册里 20 多条示例指令和应答逐字节核对，见 `tests/test_oid_rs485.py`。故障码与 CAN 版相同。

**状态**：CAN（2026-09-27）和 485（2026-09-29）的代码、按手册行为写的模拟驱动器上的回归测试都已完成，还没接真驱动器。`confirmed` 默认为 `false`：只收不发，不写驱动器配置，也不发心跳和转速。

## 文件

| 文件 | 内容 |
| --- | --- |
| `oid_codec.py` | CAN 帧编解码、故障码。纯计算 |
| `oid_modbus.py` | 485（Modbus RTU）编解码：CRC、读写寄存器、32 位字序、一帧读全状态。纯计算 |
| `oid_link.py` | 轮速 ↔ erpm 换算、左右方向、CAN 链路（Linux SocketCAN，不用装 python-can）、485 链路（pyserial，一问一答）、两条拼一条（SplitLink）、心跳、反馈、轮式里程计 |
| `oid_driver.py` | ROS 节点。对上与 `wheeltec_driver` 完全相同，控制权仲裁、上电、超时和防撞都是继承来的。另外：允许原地转；任一台驱动器报故障或掉线就停车 |
| `oid_sim.py` | 模拟驱动器：CAN 总线替身、485 替身（按两本手册的行为） |
| `oid.yaml` | 参数 |

`deployment/run_component.sh chassis` 按共享配置选驱动：`drive.type = differential`（`robot_core/robot_gen5.json`）时启动本驱动，否则启动 Wheeltec 驱动。

## 上位机（厂家 U-FOC）设置：两台分别做

下面第 3 步按这台走哪条总线做：CAN 那台看「CAN 总线」页，485 那台看「串口（485）」页。

每台用 USB 单独连上位机，依次设置：

1. 按厂家入门视频识别电机参数，记下**磁极对数**（两台应该相同，填 `pole_pairs`），设好电机最大速度。
2. 「应用程序配置 → 通用」：
   - 「应用类型」：走 CAN 的选 CAN 总线，走 485 的选串口（485）；
   - 「心跳超时时间」保持 1000 ms（本驱动每 0.1 s 给每台发一次心跳）；
   - 「超时后刹车电流」按需要设。
3. 「CAN 总线」页：
   - **「CAN 节点 ID」两台必须不同**：左轮那台填进 `can_left_id`（例如 1），右轮那台填进 `can_right_id`（例如 2）；
   - 「CAN 波特率」两台都是 500K；
   - 各项「回传时间」保持 -1，本驱动自己轮询；
   - 单路驱动器没有「发送 ID」设置，回复就用节点 ID；
   - 终端电阻：总线两端各一个 120 Ω。离车载电脑最远的那台驱动器打开「是否使用 120R 终端电阻」，中间那台关掉。车载电脑是正点原子 RK3588 时，板载 CAN 自带 120 Ω（R126），板子那端不用再加（见 `docs/RK3588_GEN5.md`）。
   485 那台在「应用程序配置 → 串口（485）」页（手册截图：115200、串口ID 1、校验位 NONE、字序大端）：
   - **「串口ID」**（即 Modbus 地址）填进 `rs485_left_id`（本车左轮，例如 1）；两台都走 485 时右轮填 `rs485_right_id`，同一条 485 上不能相同；
   - 波特率、校验与 `rs485_baud`、`rs485_parity` 一致（默认 115200、无校验）；
   - 32 位数据字序保持大端（改成小端就把 `rs485_word_order` 填 little）；
   - 本驱动每个控制周期（25 Hz）对每台写一次转速、读一次状态，115200 下一个周期约 7 ms；低于 38400 不够用。
4. 「写入应用参数到驱动器」（左边栏「应用」下载按钮），驱动器会自动重启；没自动重启就手动断电重启，设置才生效。

建议在驱动器外壳上贴「左 / 右」和 ID。设成通信控制以后，上位机只能看数据，不能再用它开电机。

## 车上

- **RS485**（本车左轮）：
  - 用正点原子 RK3588 板载的 485 口：它和 RS232 共用 UART3（`/dev/ttyS3`），**JP6 两个跳线帽插到下面**才是 485（硬件参考手册 3.29 节）。收发方向由板上电路自动切换，不用配 GPIO；
  - 驱动器的 485 A 接板子的 A、B 接 B（接反了收不到）。板上已有 120 Ω 终端电阻和偏置电阻，线长的话驱动器那端再开终端电阻；
  - 内核带 CP2102、FTDI、PL2303 和 CDC-ACM（CH9102/CH343）的 USB 转串口，**没有 CH340**：要换 USB 转 485 就选前面几种，`rs485_port` 填它的 `/dev/serial/by-id/...`；会回显的模块把 `rs485_echo` 改 true；
  - 自检（服务停着时）：`python3 -c "import serial,sys; sys.path.insert(0,'oid_protocol'); import oid_modbus as om; s=serial.Serial('/dev/ttyS3',115200,timeout=0.2); s.write(om.read_status(1)); print(s.read(29).hex(' '))"`，应回 `01 04 18 ...` 共 29 字节；
  - 一个字节都收不到（`grep ^3: /proc/tty/driver/serial` 的 `rx` 一直是 0）：先看 JP6 在不在 485 那边，再看上位机应用类型、A/B、地线；
  - 架空试转时轮子只抖一下不转，读回转速却跟着指令、位置（5010）一直是 0：驱动器的电机参数没配好，在上位机里重新配置电机（2026-09-29 左轮就是这样，重配后正常）。
- **CAN**：
  - 车载电脑是正点原子 RK3588：用板载的那一路 CAN（系统里叫 can0）。两台驱动器、IMU 的 CANH / CANL 并到同一对线上；
  - 起接口：发布激活后由 `rk3588-can.service` 开机起成 500K（手动：`sudo ip link set can0 up type can bitrate 500000 restart-ms 100`）；
  - 自检：`cansend can0 001#0F01`（问 ID 1 的转速），`candump can0` 里应能看到 ID 1 回的 `0F 01 xx xx xx xx`。ID 2 同样试一次。
- 共享配置：`/etc/rk3588/runtime.env` 里写 `RK3588_ROBOT_CONFIG=<发布目录>/robot_core/robot_gen5.json`，然后整套重启。
- **IMU**：
  - 旧车的陀螺在 Wheeltec 板上，由 Wheeltec 驱动发 `/imu`。Gen5 没有这块板，融合没有陀螺就不会给出可用定位。
  - Gen5 用瑞芬 HDA536T（CAN，挂同一条总线，节点 5，ID 0x585 / 0x605，不与驱动器冲突），由 imu 组件发 `/imu` 和 `/imu/data`。
  - 整条总线统一 500K：传感器出厂 125K，由用户自己改成 500K；周期和输出帧见 `rion_protocol/README.md`。

## 架空轮子调试

轮子离地，急停在手边，按顺序做。

1. **只收不发**（`confirmed: false`）：
   - 起服务，看 `ros2 topic echo /oid/status`：`connected` 为 true，`bus` 是 `rs485+can`、`wheel_buses` 是左 rs485 右 can，`silent` 为空（两台都在回），`erpm_read` 两个都有数，`voltage` 是电池电压；`link_last_error` 写着哪一台、什么错（例如「左轮（站号 1）：没有应答」）。
2. **认左右**：
   - 用手转左轮，`erpm_read` 应该是第一个数在变。变的是第二个，就说明左右接反了：两台都在 CAN 上时调换 `can_left_id` 和 `can_right_id`；本车一台 485 一台 CAN，就调换 `left_bus` 和 `right_bus`（以及对应的 ID）。
3. **填参数**：`pole_pairs` 填上位机识别的值。
4. **开始出力**：`confirmed: true`，重启服务。
   - app 手动页慢档往前推：两轮都往前转。哪一边往后，就把那一边的 `*_sign` 取反。
   - 摇杆打左：原地左转，左轮往后、右轮往前，`/odom` 的角速度为正，和陀螺同号。
5. **落地**：直线开 10 m，用尺量实际走了多远，按比例校 `wheel_radius_m`。
6. **急停与掉线**：
   - 急停：两轮转速给 0，按 `wheel_decel_mps2` 停下。
   - 拔掉一台的电源：状态里出现 `driver_silent:右轮`（或左轮），另一台也停，任务转 FAULT，要复位才能再开。
   - 拔掉总线：两台都会在 1 s 心跳超时后放空电机。485 那台连续 3 次没应答后只每 0.5 s 试一次，不拖慢 CAN 那台的控制周期。

## 安全

- **命令超时、反馈超时、上电**：
  - 指令 0.35 s 没更新，就给 0；
  - 反馈超过 `feedback_timeout_s`，先保持 0，超过 1 s 断电；
  - 刚连上时要等车静止，才允许上电。
  - 这几条与 Wheeltec 驱动相同。
- **一台掉线**：两台是独立的盒子，可能只掉一台。只要有一个轮子的反馈过期，就不再更新里程计。于是按反馈过期停车，并转为 FAULT；状态里会说清是哪一台。
- **驱动器心跳**：本驱动停了（进程退出、电脑死机），两台都会在心跳超时后放空电机。
- **驱动器故障**：过压、欠压、过流、堵转、失速、过温等由驱动器上报，状态里写成「左轮驱动器：堵转」这样。本驱动收到后立即停车，控制权转为 FAULT。故障消失后也要操作员复位（`/motion/reset`，app 的复位按钮）才能再开。
- **退出**：先发 1 s 转速 0，再放空两台电机（电流 0）。
