## 5. 轮趣底盘协议（摘要）

**完整协议见同目录 `PROTOCOL.md`**，这里只列最容易踩的点。

### 5.1 基本参数
- 波特率 **115200**，8N1，无流控
- 遥测帧 **24 字节**，**20 Hz** 主动上报
- 控制帧 **11 字节**
- 帧头 `0x7B`，帧尾 `0x7D`
- 校验：**BCC = 逐字节 XOR**

### 5.2 接收帧（下位机 → RK3588，24 字节，大端）

| 偏移 | 字段 | 换算 |
|---|---|---|
| `[0]` | `0x7B` | — |
| `[1]` | **inhibit 禁止控制位** | `0`=允许控制，`1`=禁止（非 0/1 则整帧拒绝）|
| `[2:4]` | X 纵向速度 | i16，÷1000 → m/s |
| `[4:6]` | Y 横向速度 | i16，÷1000 |
| `[6:8]` | Z 横摆角速度 | i16，÷1000 → rad/s |
| `[8:14]` | 三轴加速度 | i16，÷**1671.84** → m/s² |
| `[14:20]` | 三轴陀螺仪 | i16，×**0.00026644** → rad/s |
| `[20:22]` | 电源电压 | u16，÷1000 → V |
| `[22]` | BCC | `XOR(rx[0:22])` |
| `[23]` | `0x7D` | — |

### 5.3 发送帧（RK3588 → 下位机，11 字节，大端）

```
tx[0]  = 0x7B
tx[1]  = 0        普通运动模式
tx[2]  = 0        未使用
tx[3:5]  = linear.x  × 1000    (m/s → mm/s, i16 BE)
tx[5:7]  = linear.y  × 1000
tx[7:9]  = angular.z × 1000
tx[9]  = XOR(tx[0:9])
tx[10] = 0x7D
```

零帧（停车）恒为：`7b 00 00 00 00 00 00 00 00 7b 7d`

### 5.4 ⚠️ Python 移植的取整坑

官方 C 代码是 `(v/1000) + (v%1000)*0.001`。C 的整数除法**向零取整**，Python 的 `//` **向下取整** —— 负数会算错。
**Python 里直接用 `raw / 1000.0` 即可**（已验证与 C 实现逐值一致，含 −32768 边界）。

## 6. ✅ 核心问题全攻克记录与经验沉淀（2026-09-15 闭环）

### 6.1 历史疑难问题现象
上一轮遗留的核心疑问：
1. 后退/前进响应存在 1.5~2.0 秒启动延迟；
2. **原地左转 / 原地右转全程完全没反应（`vx≈0, wz≈0`）**；
3. 用户反映遥控器能正常原地打舵，但串口发纯转向指令小车纹丝不动。

### 6.2 根因彻底查明（下位机 STM32 固件源码证据）

查阅轮趣 C50X / 阿克曼底盘下位机官方源码（`balance_task.c` 第 947-970 行 与 `uartx_callback.c`）：
```c
float Akm_Vz_to_Angle(float Vx, float Vz)
{
    float TurnR, Angle_Left;

    if (Vz != 0 && Vx != 0)  // 判定条件：线速度与角速度必须同时非零！
    {
        TurnR = Vx / Vz;     // 转弯半径 R = v / w
        Angle_Left = atan(robot.HardwareParam.AxleSpacing / (TurnR - 0.5f * robot.HardwareParam.WheelSpacing));
    }
    else
    {
        Angle_Left = 0;      // 关键！当 Vx == 0 时，固件强制打正归零！
    }
    return Angle_Left;
}
```

1. **为什么上位机发纯转向无反应？**
   - 串口协议第 7..8 字节下发的是整车角速度 $\omega_z$，非裸舵机 PWM；
   - 阿克曼结构物理上无法原地旋转，下位机根据 $R = v_x / \omega_z$ 反算转角；
   - **当 $v_x = 0$ 时，下位机硬编码执行了 `Angle_Left = 0`，强制将前轮打正**！因此此前发 $v_x=0, \omega_z \neq 0$ 无论持续多久，前轮都被固件强制保持居中。
2. **为什么遥控器能原地转向？**
   - 遥控器在固件中走的是独立的中断函数 `Remote_Control()`；
   - 摇杆通道直接映射到舵机定时器 PWM 寄存器（`TIM1->CCR4`），**完全绕过了**阿克曼运动学计算与 `if (Vx == 0)` 检查。
3. **驱动电机延迟的真相**：
   - 电机与减速箱存在物理静摩擦力死区（实测速度需大于 $50\text{ mm/s}$ 才能起步）；
   - 速度积分与启动上升时间约为 1.5~2.0 秒，因此指令窗口必须 $\ge 3.0$ 秒才能观察到充分动作。

### 6.3 解决方案与实车实操经验

#### 方案 A：原地静止打舵 · 微速度触发机制（Micro-Speed Trigger）
- **核心逻辑**：发送一个极微小的虚拟线速度 **$v_x = 5\text{ mm/s} = 0.005\text{ m/s}$**，同时给角速度 $v_z = 0.020\text{ rad/s}$：
  - 下位机判定 $v_x \neq 0$，计算得到 $R = 0.25\text{ m}$，舵机偏角被限幅打满到最大物理极限（$+0.35\text{ rad} \approx 20^\circ$）；
  - $5\text{ mm/s}$ 的微弱驱动力远低于齿轮箱静摩擦死区，**驱动电机物理上完全静止不走动**！
- **实测表现**：实机运行 `user_stationary_steer.py`，前轮舵机完美向左打满并保持 4 秒后平稳回正，小车全程处于 100% 绝对静止状态（`feedback_max_vx = 0.001 m/s, stayed_stationary = true`），用户当场验收：“可以完美”！

#### 方案 B：慢速倒车弧线
- **核心逻辑**：发送 $v_x = -0.15\text{ m/s}, \omega_z = -0.35\text{ rad/s}$：
  - 小车在缓慢受控后退的同时，前轮向左打满，沿微小弧线移动，脉冲结束后自动回正并刹停。
- **实测表现**：用户当场反馈：“方向盘动了，但是往后退才动”，彻底印证了 $v_x \neq 0$ 触发阿克曼转角的固件机制。

### 6.4 硬件拓扑结论
- USB 上的 WCH 串口（serial=`0002`，`/dev/serial/by-id/usb-WCH.CN_USB_Single_Serial_0002-if00`）即为底盘控制板。
- 后轮驱动与前轮舵机均挂载在该板上，RK3588 单串口即可实现对全车的全功能驱动与状态监视。

## 7. 🚨 安全红线（血泪教训，务必遵守）

### 7.1 实际发生的事故

测试「原地左转」时，**小车突然向前开动**。原因是：
1. 命令存在 **1~2 秒延迟**
2. 停止发指令后，底盘**仍在执行之前的指令**（命令会滞后堆积）
3. AI 按"发出去立即生效"的错误假设设计测试，测试窗口太短，误判为"无响应"

最终靠**连续发送 610 个停车帧**才让车停下。**没有造成损失，但这是运气。**

### 7.2 强制规则（下一个 AI 必须遵守）

1. **绝对不要在轮子着地的情况下做运动测试。** 必须先架空。
2. **测试前必须让用户确认「物理断电开关在手边」**（电池插头/电源开关）。
3. **绝不以"发一次命令就等结果"的方式测试。** 必须持续发帧 + 持续监控反馈。
4. **任何运动测试脚本结尾必须强制发一段停车帧**（建议 ≥ 3 秒、≥ 100 帧）。
5. **测试方向必须在架空状态下先确认正负号**，否则上车后可能反着冲。
6. **不要在同一个脚本里连续测多个方向**（本次事故就是这样放大的）。
7. 用户明确说「不安全」时，**立即停止，不要再试探**。

### 7.3 现成的紧急停车脚本

板子 `/tmp/stop.py` 和 `/tmp/stopwatch.py`（临时目录，重启会丢）。核心逻辑：

```python
import serial, time
from functools import reduce
FH, FT = 0x7B, 0x7D
z = bytearray(11); z[0] = FH
z[9] = reduce(lambda a, b: a ^ b, z[0:9], 0)   # BCC
z[10] = FT
z = bytes(z)                                    # = 7b 00 00 00 00 00 00 00 00 7b 7d

s = serial.Serial('/dev/ttyACM1', 115200, timeout=0.02)
for _ in range(500):        # 持续 ~10 秒
    s.write(z)
    time.sleep(0.02)
s.close()
```

## 8. 踩过的坑（省时间，别重走）

### 8.1 Type-C 口 J17 的"读不到数据"完全是死路 —— 别再花时间

**现象**：往 J17（USB3.1 Type-C 1）插设备，`tcpm online=0`、`voltage=0`、`orientation=unknown`、无 partner，内核零事件。

**真实原因**：**两端都是从机（Rd+Rd）**。Type-C 里主机在 CC 线放 Rp 上拉、从机放 Rd 下拉；两个从机对接，谁都不放上拉 → 谁都检测不到对方。

**验证方法**（已做，结论确凿）：往 J17 插一个**充电器** → 立刻 `online=1`、`voltage=5000000`、`orientation=normal`、`partner type=host`。**证明口子、FUSB302、驱动全部完好。**

**为什么不能软切主机**（三种方法全部试过并失败）：

| 方法 | 结果 |
|---|---|
| `echo host > /sys/class/typec/port0/data_role` | ❌ `EAGAIN`（插着 PD 电源时也一样）|
| `/sys/class/usb_role/fc400000.usb-role-switch/role` | ❌ **该属性根本不存在**（目录里只有 `uevent` + `waiting_for_supplier`）|
| 运行时 DT overlay | ❌ `/sys/kernel/config/device-tree/` 不存在（虽 configfs 已挂载，但内核没编 `OF_OVERLAY`）|

**唯一可行的两条路：**
1. 改设备树：`06、linux6.12_sdk/kernel-source-clean-435f5f1d/arch/arm64/boot/dts/rockchip/rk3588-alientek.dtsi` **第 1552–1564 行** `&usbdrd_dwc3_1` 的 `dr_mode = "otg"` 改成 `"host"`，并删掉 `usb-role-switch;` 和 `port{}` 块，重编重烧。
   > ⚠️ 别改错！`&usbdrd_dwc3_0`（第 1534 行）是 **J16 烧写/ADB 口**，改了 adb 就断。
2. 走 USB-A HOST 口（天生主机）。

**结论：想在 J17 上接外部从机设备，只有改 DTS 重烧。别再试运行期方案了。**

### 8.2 `web_fetch` 工具在本环境完全不可用

```
web_fetch("https://example.com")
→ Error: URL hostname "example.com" resolves to a non-public IP address
```
**所有公网域名都被 DNS 挡成非公网 IP。** 只有 `web_search` 能用，但它**只返回 URL 列表，不返回正文**。

**✅ 破解办法：用板子当代理！** 板子有完整公网访问。
```bash
adb shell "curl -s 'https://api.github.com/search/repositories?q=wheeltec'"
adb shell "curl -s 'https://api.github.com/repos/OWNER/REPO/contents/path/to/file' -o /tmp/x.json"
# GitHub API contents 返回 base64，本地解码
adb shell "python3 -c \"import json,base64; d=json.load(open('/tmp/x.json')); open('/tmp/f','wb').write(base64.b64decode(d['content']))\""
```
> ⚠️ `raw.githubusercontent.com` **只有 IPv6 AAAA 记录**，板子走不通。**必须用 API contents 接口。**

## 9. 有用的工具与技巧

### 9.1 usbmon —— 确认串口到底发出去了什么（强力推荐）

```bash
# 找到设备在 bus5 上的 devnum
adb shell "cat /sys/bus/usb/devices/5-1.4.1/devnum"
# 抓该设备的 USB 流量（一边抓一边发指令）
adb shell "( timeout 8 cat /sys/kernel/debug/usb/usbmon/5t | grep -a ':009:' > /tmp/usb.log ) &"
...
# 看 OUT 传输（Bo = bulk out，就是我们写的）
adb shell "grep -aE ' (Bo|Co|So):009:' /tmp/usb.log"
```
输出示例（`S`=submit，`C`=complete，`status 0`=成功）：
```
S Bo:009:02 -115 11 = 7b000000 00000000 c8b37d
C Bo:009:02 0 11 >
```
> 注意：usbmon 是**按总线**抓的，bus5 上有相机（12 MB/s），必须边抓边 `grep` 过滤，否则文件巨大。

### 9.2 读 Type-C 端口管理器（TCPM）的芯片级状态

```bash
# 比 sysfs 的 typec 更底层，直接反映 FUSB302 芯片状态
cat /sys/class/power_supply/tcpm-source-psy-5-0022/online      # J17
```
