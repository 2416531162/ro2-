# 瑞芬 HDA536T 动态倾角传感器（Gen5 的 IMU）

旧车的陀螺在 Wheeltec 板上，由它的驱动发 `/imu`。Gen5 没有这块板，融合没有陀螺就给不出可用定位（app 显示「IMU 数据中断」，车不会开）。Gen5 用瑞芬 HDA536T：内置陀螺和加速度计，自带卡尔曼滤波算横滚、俯仰，CAN 输出，和两台欧艾迪驱动器挂同一条总线。

协议依据厂家《HDA536T-CAN2.0A/B 动态倾角传感器技术手册》V1.4（2024-9-9）。编解码已按手册里的示例报文逐字节核对，见 `tests/test_hda536t.py`。

**状态（2026-09-27）**：代码和按手册行为模拟的传感器上的测试已完成，还没接真传感器。

## 文件

| 文件 | 内容 |
| --- | --- |
| `hda536t_codec.py` | 数据帧解码、设置指令、NED → ROS REP-103 换算。纯计算 |
| `hda536t_imu.py` | ROS 节点：发 `/imu`（原始）、`/imu/data`（带传感器算的姿态：app 显示横滚俯仰，航向角进融合）、`/imu/status`。只收不发 |
| `hda536t_setup.py` | 上车前设置传感器（不需要 ROS） |
| `hda536t.yaml` | 参数 |

`deployment/run_component.sh imu` 按共享配置选：`drive.type = differential`（`robot_core/robot_gen5.json`）时启动本驱动，否则还是 `imu_filter_madgwick`（旧车）。所有带 `line` 的部署组合都带 `imu`。

## 输出

- `/imu`（`sensor_msgs/Imu`）：陀螺（弧度/秒）+ 加速度（米/秒²），不带姿态（`orientation_covariance[0] = −1`），和旧车一样。融合只用 z 轴角速度。
- `/imu/data`：同上，再带传感器自己算的姿态。横滚、俯仰相对地理水平面（手册：动态 ±0.1°），偏航上电为 0，是相对值（没有磁力计）。
  - **Gen5 的融合用这个航向角推算航向**（2026-09-28 用户要求，见 `docs/GNSS_FUSION.md`「Gen5：航向推算用 IMU 航向角」）：两次测向之间转了多少按它的增量算，朝哪仍由双天线定。
  - 行驶中别发「航向清零」。融合会把这一跳当尖峰丢掉，但没有必要。
- 坐标系 ROS REP-103：x 车头、y 左、z 上；左转角速度为正，横滚左侧抬起为正，俯仰车头压低为正。传感器本身是 NED（x 车头、y 右、z 下），驱动里把 y、z 取反。
- `/imu/status`（JSON，1 Hz）：各帧频率、自检、安装方式、温度、姿态、`problem`（给人看的原因，正常时为 null）。
- 自检失败、传感器报的安装方式不是水平、没有陀螺帧时，不发 `/imu`，`problem` 写明原因。

## 选型与安装

- **型号**：本车用 `HDA536T-C2`（CAN2.0A 标准帧，和驱动器一样；2026-09-27 确认），`hda536t.yaml` 的 `extended` 保持 false。换成 C3（CAN2.0B 扩展帧）时才改 true，设置脚本也要加 `--extended`。
- **安装方式**：型号里的 T = 水平安装。平放在车架上，**外壳上的 X 轴箭头朝车头**，四颗 M4 螺丝拧紧，不要装在会晃的支架上。装在车上哪个位置都行，角速度处处相同。
- **供电 9–36 V**：Gen5 电池是 24 V（满电也不到 30 V），可以直接从电池取电，走开关和保险，不用降压模块。
- **接线**（M12 5 针）：1 棕 PE、2 白 电源正、3 蓝 GND、4 黑 CAN_H、5 灰 CAN_L。CAN_H / CAN_L 并到驱动器那对线上，分支尽量短。
- **终端电阻**：整条总线只能在两端各有一个 120 Ω。断电后在 CAN_H、CAN_L 之间量电阻，应该约 60 Ω；约 40 Ω 说明多了一个，要去掉。

## 设置传感器（在车载电脑上做一次）

整条总线统一 500K：两台驱动器、传感器、车载电脑的 can0（`sudo ip link set can0 up type can bitrate 500000`）。

传感器出厂是 125K，**波特率由用户自己改成 500K**，节点号保持 5。除了波特率，还有两项要改，改完都要重新上电才生效：
- 输出周期 20 ms（50 Hz），出厂是 100 ms；
- 输出角度 + 加速度 + 陀螺三帧（MASK = 7），出厂只发角度帧。

这两项可以用你自己的工具改，也可以在 500K 的总线上用本目录的脚本改：

1. 先听一下（传感器已是 500K）：
   ```bash
   python3 rion_protocol/hda536t_setup.py show
   ```
   应看到数据帧 ID `0x585`，自检 ok，安装方式「水平安装」。还没改周期和输出帧时，角度约 10 Hz，问题写「没有陀螺帧」。
2. 改周期和输出帧：
   ```bash
   python3 rion_protocol/hda536t_setup.py gen5
   ```
   两项都应「成功」。
3. 传感器断电再上电，再 `show` 一次：三种帧都约 50 Hz，问题「没有」；驱动器的 ID（1、2）也在总线上。

## 上车核对（车停着、轮子不动）

起服务后：

1. `ros2 topic echo /imu/status`：`problem` 为 null，`陀螺` 约 50 Hz。
2. **加速度**：车停在平地上，`ros2 topic echo /imu` 的 `linear_acceleration.z` 约 +9.8。读成 −9.8 就把 `invert_accel` 改 true，重启 imu 组件。
3. **转向方向（最重要）**：用手把车往左转（从上往下看逆时针），两项都要对：
   - `/imu` 的 `angular_velocity.z` 应为正，并且和 `/odom` 的角速度同号；
   - app 姿态卡片的「IMU 航向」应往左转的方向变（左转为正）。
   
   反了先别开车，把现象告诉我。开起来以后，融合也会在原地转向时拿 IMU 和轮速里程计比方向，反了就报「IMU 转向与轮速相反」并锁住不让开。
4. **姿态**：app 手动页的姿态卡片。垫高车头时俯仰应显示「车头高」；垫高左侧时横滚应显示「左侧高」。
5. **融合**：RTK 固定、车静止 1 分钟，app 上定位应显示可用，不再报「IMU 数据中断」。

## 其余

- 陀螺零偏：融合在车静止时自己估，传感器用出厂的「快速启动」就行。长时间用后零偏变大（手册说大于 0.5°/s）时，可按手册第 9 条清零偏。设置脚本还没做这一项。
- 本驱动从不往总线发东西。设置用 `hda536t_setup.py`，设置期间先停 imu 组件（`sudo systemctl stop rk3588-perception@imu`）。
