# 2026-10-02 轮程融合增量发布

基于车上版本 `59b3550a128c5578`、源提交 `75ee98028969054e4fa1b43c7a8acb6f77107d58`。
保留当前长直线控制参数、定位暂停渐停、侧置喷头对准点、作业数据删除及水泵功能。
本次部署授权来自用户「通过平板部署到车」，不包含运动或开泵测试。

本次只改轮程与融合链路：

- 左右轮速度与累计角度按各自主机回复时刻对齐；RS485 阻塞查询完成后标记时间。
- 累计轮程的区间平均速度插回融合历史，修正同一区间，避免与旧 `/odom` 重复输入。
- 可信卫星、近直行、无运动矛盾时，以非重叠 8 m 数据段学习共同轮程比例；至少 3 段才逐步应用。
  每段至多修正配置比例的 0.5%，只影响以后位移；遮挡时冻结，不写入磁盘。
- 比例误差保留相关 GNSS 误差、段间差异、未应用的差值及约 0.5% 下限；没有学够仍用配置的 2%。
- 详细轮程与 IMU 或可信 GNSS 速度矛盾时报告 `wheel_motion_conflict`，不永久停用 IMU。
  近期矛盾未消除且卫星中断时停止控制许可；加入时间误差及运动矛盾余量。
- Gen5 默认开启 `wheel_increment_enabled` 和 `wheel_scale_auto`；旧驱动保留单一 `/odom` 兼容。
  `calibration().wheel_motion` 报告来源、已应用比例、比例余量、学习段数和冲突。
- 记录 `/wheel/odometry` 供后续实车核验，字段见 [WHEEL_ODOMETRY.md](WHEEL_ODOMETRY.md)。

5 s 兜底上限、原喷头误差限值及随机过程噪声不变。两轮共同空转、侧滑和共同 GNSS 漂移仍可能不可观测。
此前 31 组配对传感器仿真说明主要改善已标定后的沿向漂移，不代表万向轮摆动或整车闭环精度已经改善。
旧实车记录缺少两轮高频累计角度及各自回复时间，不能用于验证新链路或据此补造输入。

部署通过平板的车辆 Wi-Fi，走现有签名包上传、车端验签、自检、空闲激活及失败回退流程。
部署后只核对服务、版本、实际轮程消息和融合接入状态。
