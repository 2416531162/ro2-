# 原地转向收尾的坡上回退恢复

2026-10-11。用户确认：原地转向快对准时，推一下又退回，随后报错中止。

## 原因

`SectionTracker._turn` 原来有两个不可恢复的标志：开始减速后 `_pivot_slowing` 禁止再次增加角速度；
预测到位后 `_pivot_braking` 持续撤掉转向指令，即使实际车头已经回退。角速度指令一到零，原地转向状态
立即结束，后续只能等待停稳或重新消耗补转次数。

因此短转向指令在坡载/万向轮阻力下未真正完成，或者撤力后回退时，预估模型会比实际转动更乐观，
出现重复推一下、退回、耗尽补转次数的情况。自动作业期间驱动层本来就禁止自动放空电机，问题不在放空定时器。

## 改动

- 零速指令发出后，保留本次转向目标，继续检查实际运动；在途转向指令排空并连续停稳后才结束。
- 收尾阶段实际欠转超过原有的 `pivot_min`（默认 5°）、反向转速超过 0.02 rad/s 持续 0.15 s，恢复同一次转向。
- 已撤力且延迟队列应当排空后，仍实际欠转超过 5°，也恢复；不用等重新补转消耗次数。
- 恢复阶段低速持续推到实测到位，不能仅靠未实现的指令积分再次立即撤力。默认恢复转速上限 0.2 rad/s，
  同时服从原最大转速、最低有效转速和角加速度配置。
- 保留原来“停稳后差 5° 以内交给后续直行纠正”的规则，避免追逐正常的小回弹。
- 同一次恢复不清零 20 s 转向超时。真正堵转仍中止；定位失效、暂停和停止仍输出零。

新状态字段 `pivot_recovering`、`pivot_recoveries` 用于观察是否正在恢复及当前尝试恢复次数。

## 验证

53 项相关回归通过，覆盖转向反馈、启动/换段、暂停恢复、定位失信、真实堵转，以及上一版横偏修复。
修正前，“撤力后车还在回退却结束转向”和“同一次转向应恢复推力”两项回归失败；修正后通过。

对照模型：控制周期 20 ms、执行延迟 0.325 s、一阶响应 0.05 s；小转速需要连续驱动 0.4 s 才能起动，
撤力后释放最多 6° 的有限回弹。该模型用于敏感性验证，不是现场坡度/摩擦的实测标定。
