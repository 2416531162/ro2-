# Gen5 两路 IMU 选择与对比

## App 使用

入口为「更多 → IMU 选择与对比」。页面并列显示 HDA536T（CAN）和 IMU762（USB）的横滚、俯仰、航向、陀螺 Z、温度、接收频率和控制入口频率；IMU762 另显示校验坏帧和序号缺口。

先结束当前任务、锁定手动控制并停稳，再点目标 IMU 的切换按钮。界面只按车端确认的来源显示「当前使用」，网络转发成功不当成切换成功。目标传感器的姿态和角速度必须在 0.2 秒内更新；实际底盘反馈需新鲜且持续停稳至少 0.3 秒。

「同步对比起点」仅给本页的两路 Δ 航向设相同显示起点，不清零模块、不改变车辆定位或控制参考。两路航向可能有不同上电零点，应主要比较 Δ 航向、漂移和角速度。连接中断或数据失去新鲜度后重新同步显示起点。

## 接收与控制

IMU762 按固定 460800、8N1 接收，保留模块 400 Hz 输出。接收线程解析所有完整帧，控制线程每 20 ms 取最新帧，不把 400 Hz 发布量灌入定位控制队列。

板子缺少 CH341 内核驱动时采用系统已有 libusb。只自动匹配唯一 CH340（1a86:7523），不解绑内核驱动、不扫描试开 GNSS 串口。若转换器已经有内核驱动，设置 `IMU762_PORT` 为该模块的专用串口；若有多个 CH340，设置明确设备路径。不同时运行独立读取器和定位节点内置接收器。

默认选 HDA536T。切换选择保存为融合配置同目录的 `imu_source.json`，重启后恢复。模块拔出会报告数据中断，不自动切换到另一个 IMU。此功能不改变控制参数、接入走法、助跑长度或喷涂资格。

换源后重新初始化融合推算、IMU 零偏和跨线对齐，保留坐标原点、融合配置和已学到的底盘轮程比例。水平零点分别使用原 `imu_zero.json` 和 `imu_zero-imu762.json`，未标定的新来源从无水平零点开始。定位需重新稳定，不能沿用旧源的直行目标。

## 消息与记录

App 指令：`{"type":"imu_source","source":"imu762","id":"唯一编号"}`，来源只接受 `hda536t` 或 `imu762`。Web 服务转发到 `/line/command`；按同一 id 查询 `line.last_result` 的最终执行结果，重复 id 不再次重置融合。

`line.imu_sources` 包含 `supported`、`active`、`revision`、`blocked`、`error` 和 `sensors`。每路传感器包含新鲜度、角度、陀螺、温度和速率；无法接收时保留具体错误。

| 话题 | 用途 |
|---|---|
| `/imu/data` | 原 CAN IMU 姿态，保留原驱动 |
| `/imu762/data` | 新 USB IMU 最新姿态，最多 50 Hz |
| `/imu/selected/data` | 当前控制来源，供 Gen5 IMU 定向直行使用 |

作业记录同时保存这三个话题，可根据当前来源和两路读数复盘。定位节点直接将已选源样本送入融合和路线跟踪，不订阅自己的选源输出，避免重复输入。

## 当前验证边界

App Kotlin 编译和修改文件的 Python／Shell 语法检查通过。此前独立读取器已读到真实 IMU762 数据；本次双源切换尚未在板子上安装验证。没有转动轮子、写车辆驱动参数或再次改变模块参数。

手册 FRD 文字与实物静止加速度符号存在差异，代码暂按协议文字转换；安装后需静态核对左转时两路航向和陀螺 Z 是否同向，再进行对比驾驶。
