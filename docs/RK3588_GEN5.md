# Gen5 用正点原子 RK3588 做车载电脑

2026-09-28 起，Gen5 的车载电脑从 Jetson Orin Nano 换回正点原子 ATK-DLRK3588B。本仓库最早就在这块板上开发，代码同时支持两块板：ROS 2 Jazzy（RK3588，Ubuntu 24.04）和 Humble（Jetson，Ubuntu 22.04），由 `radar_system/ros_env.sh` 自动选。

Gen5 只部署 `rtk` 组合：网页 / app 链路、RTK、走线、IMU、作业记录，加底盘驱动。

**状态**：只改了代码和文档，还没在板子上跑过。下面「上板核对」逐项做完才算换好。

## 连接板子（沿用 `wheeltec_protocol/交接文档.md` 的做法）

- 用 adb，账号是 root：
  - USB 线插 **J16**（USB3.1 Type-C 0，adb / 烧写口）；
  - 或者走 WiFi：`adb connect <板子IP>:5555`。以前在 192.168.2.x 路由器上是 `192.168.2.173`，换了网络地址会变。
- adb 的几个坑（交接文档 8.3）：
  - `adb shell` 里起后台进程要用 `setsid nohup ... > log 2>&1 < /dev/null &`；
  - Python 要加 `-u`；
  - `/tmp` 重启就清空。

## 硬件

- **供电**：板子只有一个 DC12V 输入口，标配 12 V 2.5 A 适配器，RK3588 功耗不小。车上电池是 24 V，要加一个 24 V → 12 V 降压模块，输出至少 3 A，建议 5 A。不能把 24 V 直接接到板子上。
- **CAN（Gen5 的两台驱动器 + IMU）**：
  - 板子上有 1 路 CAN：RK3588 的 CAN1（m1 引脚 GPIO4_B2 / GPIO4_B3），经 TPT1051V 收发器引到板上的 CANH、CANL 端子（硬件参考手册 3.23 节）。两台欧艾迪驱动器、HDA536T 都并到这一对线上，CANH 接 CANH、CANL 接 CANL。
  - 板上已经焊了终端电阻 R126（120 Ω），所以板子这端的终端已经有了。总线另一端离板子最远的那个设备打开 120R，中间的设备都关掉。断电后量 CANH–CANL，应约 60 Ω。
  - 正点原子 Linux 6.12 SDK 的设备树（`rk3588-alientek.dtsi`）已打开 `can1`，用的是 m1 引脚。板上正在跑的内核 `CONFIG_CAN_RAW`、`CONFIG_CAN_ROCKCHIP`、`CONFIG_CANFD_ROCKCHIP` 都是 y。只有这一路 CAN 时，系统里应叫 `can0`，本仓库都按这个名字写。
  - 内核没编 `gs_usb`，常见的 USB-CAN 适配器（candleLight 一类）插上用不了。就用板载 CAN。
- **RS485（本车左轮驱动器，2026-09-29）**：左轮那台欧艾迪驱动器是 485 版（Modbus RTU），右轮还是 CAN。
  - 用板载 485 口：和 RS232 共用 RK3588 的 UART3（`/dev/ttyS3`），**JP6 两个跳线帽插到下面**才是 485（硬件参考手册 3.29 节）。SP3485 收发方向由电路自动切换，当普通串口用。
  - A 接 A、B 接 B。板上已有 120 Ω 终端电阻（R119）和偏置电阻。
  - `oid_protocol/oid.yaml` 里 `left_bus: rs485`、`right_bus: can`；站号、波特率与上位机一致，见 `oid_protocol/README.md`。
  - 内核没编 CH340（`ch341`）驱动：要改用 USB 转 485，选 CP2102、FTDI、PL2303 或 CH9102/CH343（CDC-ACM）的。
- **RTK 接收机（UM982）**：USB 转串口是 CP2102N，内核里有 `cp210x`。`rtk_node` 默认按 `/dev/serial/by-id/usb-Silicon_Labs_CP2102N...` 找，和 Jetson 上一样。
  - 要插 **USB-A 口**（板上 CH334R 集线器下面的口）。
  - **J17**（USB3.1 Type-C 1）只能当从机，插设备读不到，要改设备树重烧才行（交接文档 8.1）。
- **车载屏幕**：接板子的 HDMI。

## 系统和依赖

- 正点原子的 Ubuntu 24.04 镜像（Linux 6.12），Python 3.12。
- ROS 2 Jazzy：`ros-jazzy-ros-base` 就够了，`rtk` 组合用到的 rclpy、sensor_msgs、nav_msgs、geometry_msgs、std_srvs、tf2_ros 都在里面。Gen5 不用 `imu_filter_madgwick`，姿态由 HDA536T 自己算。
- Python：`python3-numpy`、`python3-serial`、`python3-opencv`（网页服务要用）。
- 车载屏幕：`gir1.2-webkit2-4.1`。Ubuntu 24.04 已经没有 WebKitGTK 4.0，`car_display_window.py` 已改成先用 4.1、没有再用 4.0。

## 部署

1. 把 `deployment/runtime-rk3588.env.example` 复制成板子上的 `/etc/rk3588/runtime.env`。里面写了 `ROS_DISTRO=jazzy`，以及 `RK3588_ROBOT_CONFIG=robot_core/robot_gen5.json`；相对路径按当前发布目录算。
2. 激活前先在板上跑冒烟测试。它用真的 rclpy（Jazzy）把 rtk、line、imu、oid 四个节点构造一遍：
   - imu 用假总线；
   - oid 只收不发，没有 can0 也能跑。
   失败就不要激活：
   ```bash
   bash /opt/rk3588/releases/<发布号>/deployment/smoke.sh /opt/rk3588/releases/<发布号>
   ```
3. 发布、激活（与 Jetson 相同，见 `deployment/manage.py`）。
   - 这块板一直用 root（`adb shell` 进去就是 root，没有 sudo），所以要写 `--user root`，与以前一样用 root 跑服务。
   - 不写 `--user` 时，默认用执行 sudo 的账号，没有 sudo 就是 Jetson 的 wheeltec。这块板上没有 wheeltec，activate 会直接报错，不会写出起不来的服务。
   ```bash
   python3 deployment/manage.py activate /opt/rk3588/releases/<发布号> --user root
   ```
4. activate 会装上并启用 `rk3588-can.service`：开机把 can0 起成 500K，总线出错（bus-off）后 0.1 s 自动恢复。它排在底盘驱动和 IMU 前面。没有 can0 的车（旧车）会自动跳过。
5. 车载屏幕：在板子的桌面里执行一次 `bash deployment/install_display.sh`。

## 从 Jetson 带过来的文件（`~/rtk/`）

RTK 和走线的配置、状态都在服务账号的家目录下。Jetson 上是 `/home/wheeltec/rtk/`，这块板用 root，就是 `/root/rtk/`：

| 文件 | 带不带 | 说明 |
| --- | --- | --- |
| `ntrip.env` | 带 | CORS 账号，权限 600。也可以不带，在 app 的「CORS 设置」里重新填 |
| `fusion.json` | **不带** | 旧车的天线杆臂、安装偏差。Gen5 天线位置不同，要重新量 `antenna_xy`（见 `docs/DIFFERENTIAL_DRIVE.md`）和天线离地高度 `antenna_height_m`（倾斜补偿用，见 `docs/GNSS_FUSION.md`「倾斜补偿」）。例：`{"antenna_xy": [0.30, 0.19], "antenna_height_m": 0.42}`（数字要换成实测） |
| `line_state.json` | **不带** | 旧车前轮舵机的零位修正，差速车用不上 |
| `route.json` | 随意 | 车上存的路线，app 可以重新发 |
| `runs/` | 不用带 | 旧车的作业记录 |

UM982 接收机自己的设置（输出日志、基线）存在接收机里，跟着接收机走，不用重配。

## 上板核对

1. `ip -details link show can0`：`state UP`，`bitrate 500000`，`restart-ms 100`。
2. `candump can0`：能看到驱动器（ID 1、2）的回复和 IMU 的 `0x585`。
3. `python3 rion_protocol/hda536t_setup.py show`：三种帧约 50 Hz，没有问题。IMU 波特率由用户自己改成 500K，周期和输出帧用 `gen5` 设，见 `rion_protocol/README.md`。
4. `ros2 topic echo /oid/status`、`/imu/status`：驱动器都在回，IMU `problem` 为 null。然后按 `oid_protocol/README.md` 架空轮子调试，按 `rion_protocol/README.md` 核对陀螺方向。
5. app 连车：定位可用；姿态卡片的 IMU 来源是 hda536t；车载屏幕全屏显示。
6. **倾斜补偿**：先按 `rion_protocol/README.md` 第 4 步核对姿态方向（垫高车头显示「车头高」、垫高左侧显示「左侧高」），方向对了再在 `/root/rtk/fusion.json` 里填 `antenna_height_m`，重启 line。app 姿态卡片应显示「倾斜补偿」和补偿量。验证：车停着，把左后轮垫高约 5 cm（开上木板停稳也行），看 app 路线页「诊断」里「RTK 与融合推算之差」图的侧向曲线：不补时会跳到约 −天线高 × sin(横滚)（0.4 m、4° 约 −2.8 cm）再慢慢回来，补了应基本不动（RTK 本身有几毫米的抖动）。注意原地转 180° 查不出这个偏差：不补时车的位置总是往坡下偏，转过来还是往坡下偏。
7. `free -h`：看板子是 4 / 8 / 16 GB 哪一档，`rtk` 组合占用不大。

## 要注意

- 车载屏幕的「回到桌面」是给 X11 窗口管理器发消息。Ubuntu 24.04 桌面如果是 Wayland 会话，这个按钮可能不灵，要上板看；不灵就在登录界面选 Xorg 会话。
- **板上的旧系统**：以前在 `/root/radar_system`，用 `start_all.sh` 手动起，没有开机自启。
  - 装了新发布（`/opt/rk3588`，systemd 开机自启）以后，**不要再跑旧的 `start_all.sh`**，否则会起两套同名节点、抢串口。
  - 如果 9 月中旬也用 manage.py 装过 `/opt/rk3588`，activate 会用同名服务覆盖掉。
- **`rk3588-bantu.service`（`full_inspector`）留着**：它是板子的硬件状态页（8888 端口）、蓝牙和风扇温控，只读设备列表，不占串口和 CAN，和本车的服务不冲突。
- **动车前**：看交接文档第 7 节「安全红线」。先架空轮子、断电开关在手边，持续发帧、持续看反馈。欧艾迪驱动的调试步骤（`oid_protocol/README.md`）就是按这个写的。


## 2026-09-30 运行鲁棒性修复

以用户指定的 `5fb8c1705ed1f410` 为基底，合并修复后发布为 `5934dbf7f04e0eee`。原版的
`line_cascade.py`、`line_mission.py`、`heading_hold.py` 保持字节一致；未带入本机其他未部署变更。

- IMU 接收与状态统计共用可重入锁，避免 CAN 线程更新队列时状态线程遍历导致的
  `RuntimeError: deque mutated during iteration`（当天 17:25 板端实际发生，并已离线复现）。
- RS485 写入设置超时，输出队列采用有截止时间的轮询，写入、排空和应答共用截止时间；移除无界的 `flush()`。
- 六个核心服务向 systemd 注册 20 秒看门狗。仅当 ROS 主循环及各自必需的 I/O / HTTP 循环都有进展时喂狗；
  单个后台线程仍存活不能掩盖 I/O 卡死。正常循环报告传感器缺失不触发重启。第三方旧 IMU 程序不被强制启用此机制。
- Web 主线程统一处理 SIGTERM/SIGINT，退出 HTTP 循环并关闭 ROS；ROS 线程异常退出时主进程也失败退出，交由 systemd 恢复。

看门狗负责服务恢复，不承担即时制动；既有运动指令超时、反馈失效停车和驱动器心跳机制保持不变。

合并版本通过 160 项相关回归（另有 346 项子测试）及板端 rtk / line / imu / oid / jobrec 冒烟。
独立无硬件测试服务验证过看门狗超时和自动重启；真实 ROS Web 隔离测试中 SIGTERM 退出约 0.25 秒。
完整工作区测试与旧部署的 CORS 协议有已存在的差异，未夹带修复；详情、精确补丁及部署后检查记录在
`artifacts/robustness-20260930/requested-release.json` 和同目录 `requested-fix.patch`。
