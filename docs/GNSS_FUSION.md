# RTK / IMU / 轮速平面定位融合

实现：`radar_system/gnss_fusion.py`。仿真：`radar_system/tools/fusion_sim.py`。
该模块只依赖 Python 标准库，仿真和测试另用 NumPy；不导入 ROS，不读写配置，不连接硬件。
本文现行规则对应 **2026-10-04 的本地代码**。本次更新修复遮挡后的航向恢复与起步确认，尚未部署。
文末 2026-09-25 验收及明确标为历史的实车记录保留用于追溯，不能代表当前 Gen5 的规则或实车效果。

## 卫星为准，删掉否决卫星的检查（2026-10-05 用户规则，优先于下文各节）

用户原话：
- 「只要 RTK 满足双固定，测向满足 0.3 到 0.5，就必须不能报任何定位错误」
- 「即使没有轮速和 IMU 的数据，也可以靠 RTK 作业，轮速和 IMU 永远只是辅助」
- 「原来的检查必须删除，这种检查是不合理的」

### 已删除（代码、参数、原因代码都去掉）

下文各节里提到这些的内容只作历史：

| 删掉的检查 | 原来的代码 / 原因 |
|---|---|
| 双天线位置互检否决固定解 | `DualAntennaCheck` 的 suspect / pending，`rtk_suspect`，`dual_check_*`、`dual_ok_*`、`dual_stale_s` |
| 推算位移互检 | `_displacement_check`，`gnss_displacement_conflict`，`displacement_*` |
| 测向基线带 0.35–0.45 m | `heading_length_band_m`，`baseline_off` |
| 测向和 IMU 不一致时冻结测向，要连续 1 s 质量确认才接回 | `heading_conflict`，`_heading_recovery_ready`，`heading_disagreement` |
| 位置和推算差超过 0.3 m 先停车重定位 | 改成直接按卫星接回、输出对齐 |
| 任务层「定位与卫星差太多」停车 | `position_mismatch`，`MISMATCH_M` |
| 任务层推算误差预算停车 / 限速 | `_hold_budget`，`rtk_hold_budget_*`、`paint_budget_exceeded`、`transit_budget_slow` |
| 起步 / 继续前的卫星确认 | `_rtk_unconfirmed`，`rtk_not_confirmed` |
| 定点画线的「航向跳变」 | `line_cascade` 的 `heading_jump`：偏移一直照学，开始时差超过 `jump_deg` 直接重定 |

`line_node.OBSOLETE_FUSION_KEYS` 列了删掉的参数，车上 `~/rtk/fusion.json` 里还写着这些参数时会被丢掉，照常启动。

### 保留的部分

- 互检偏差只用来给固定解降权（`dual_weight_m`）：不丢帧、不停车。
- 没有固定解（掉信号、浮点）时最多推算维持 `rtk_hold_s`（5 s），超时停车，恢复后自动继续。
- 轮速、IMU 都没有且卫星不可信时，没有定位来源，照旧不可用。
- 推算期间的不确定度上限：`heading_uncertain` 照旧生效；`position_uncertain` 在最近一次固定解后 `rtk_hold_s` 以内只提示、不停车
  （2026-10-07：固定解刚断、还没满 `fixed_timeout_s` 的那几拍原来会因它停车再起步，见下面「卫星出问题时 IMU 无缝接上」）。

### 卫星出问题时 IMU 无缝接上（用户：「能不能无感 imu 接上继续走，不能停」）

| 情况 | 处理 |
|---|---|
| 测向无效（基线超出 0.30–0.50 m、测向浮点），主天线还是固定解 | 位置照用卫星，航向由 IMU 接着推；IMU 正常就一直可用，`heading_uncertain` 只提示 |
| 主天线没有固定解 | 轮速 + IMU 推算，最多 `rtk_hold_s`（Gen5 9 s：满 8 s 先停喷），超时停车。从断的那一拍起位置不确定度超过 3 cm 也只提示（`position_uncertain`），不停车、不停喷、不降速（2026-10-07 用户：「不能停车，丝滑切换，也不能停喷」） |
| 卫星回来 | 控制输出按 `rejoin_rate_mps`（4 cm/s）平滑挪回卫星；差超过 `BLEND_MAX_M` 直接对齐 |
| 输出航向 | 按 1°/s 平滑跟融合航向；只有卫星可信而 IMU 断着时不限速，直接跟测向 |

模拟（直行 0.5 m/s，测向断 2 s，主天线浮点 2 s，回来时卫星偏 5 cm）：全程可用；回来时输出每 20 ms 最多挪 4.4 mm（改前 14 mm）。

### 卫星可信

可信的条件如下，三样都要在 `TRUSTED_FRESH_S`（1 s）内来过：
- 主天线 `NARROW_INT`；
- 副天线（BESTNAVH）`NARROW_INT`；
- 测向整周固定，且基线 0.30–0.50 m（`TRUSTED_BASELINE_M`）。

条件按到达顺序判，结果跟样本存下，历史重放时不变。可信时按下面处理。

**输出**
- `usable_for_control=True`，`quality='RTK_FIXED'`，`reasons=()`，`rtk_trusted=True`。
- `/line/status` 的 pose 和作业记录都带 `rtk_trusted`。
- 任务层不限速。

**测向和推算对不上时**
- 按测向接回。
- 控制输出不按 1°/s、4 cm/s 限速；差超过 `BLEND_MAX_M` 直接对齐。

**轮速或 IMU 断着时**
- 位置直接取卫星，不降权、不做离群放大。
- 轮速断了用卫星地速（多普勒）推，不要求 IMU、不限时。
- IMU 断了航向直接取测向，两帧之间按测向算的转速推。
- `pose()` 最多外推 `TRUSTED_EXTRAPOLATION_S`（0.5 s）。

**代价**：两根天线一起错（共模跳）、主天线固定解错了，都不再抓。

### 模拟验证

`/tmp` 一次性脚本，10 Hz，卫星延迟 0.1 s：
- 四种传感器都在：全程可用、无原因；副天线断了也照常可用。
- 停车 3 s 后断掉轮速和 IMU，再以 0.5 m/s 直行：一直可用。起步 0.25 s 内落后 7 cm，之后 ≤1 mm。
- 基线 0.32 m 照常用。
- 没有 IMU 时原地 0.5 rad/s 转：车头落后 2.9°，停下 1 s 内对齐。

## 单天线流动站（2026-10-07）

平板可以改转一台单天线接收机（HCYTJ，蓝牙 SPP），装在双天线的右天线位置（后轴中心前 0.234 m、右 0.212 m，
`line_node.SINGLE_ANTENNA_XY`）。`um982.Um982Stream` 收到通过校验的 `$INS.NAVI` 标成 `antenna_mode = single`，定位取这句
（接收机自己的组合导航解，5 Hz；字段见 `um982.parse_ins_navi`，2026-10-07 实抓与同一秒 GGA 逐项对过）。GGA 只有 1 Hz，不当定位
（用户：「不要识别这个 gga，用他的 5hz 融合」）；INS.NAVI 不带定位质量，每帧按同一秒或稍早 1.5 s 内那条 GGA 的质量标
（4 → `NARROW_INT`、5 → `NARROW_FLOAT`，没有这样的 GGA 按 NONE 不用）。INS.NAVI 也不带精度：取同样时间窗内那条 `$GNGST`
报的纬度、经度 1σ（`um982.gst_sigma`，2026-10-07 起接收机开了 GST，固定时水平约 0.7 cm；高程精度用户说不用，不取）给融合，
状态里 `sigma_h` 如实报；没有 GST 时固定解按 1 cm、浮点按 0.3 m 假定，状态里 `sigma_h` 报 null。按 σ 的既有门槛
（融合观测权重、直线卫星纠偏 `fit_max_sigma_m`、轮速标定）和双天线一样按接收机报的值生效，不另加单天线规则。PDOP（`$GNGSA`，2 s 内收到的）小于 3 才可信，3 及以上、或没有 PDOP 的帧一律不用（用户规则，
`um982.INS_MAX_PDOP`）：fix 消息照实报解类型、带 `pdop_ok: false`，走直线节点按没有解交给融合（IMU 推算维持，满 8 s 停喷、
9 s 停车）。这时融合只看到没有解（`rtk_hold` → `rtk_fixed_timeout`），任务层把真实原因 `pdop_high`（有 PDOP，不小于 3）/
`pdop_missing`（2 s 内没收到 PDOP）插到位姿原因最前面（`LineMission._fusion_pose`，只在最近一帧单天线定位 1.5 s 内时），
作业中提示也按它说（「单天线 PDOP 3.4（要小于 3），卫星位置不用，按 IMU 推算继续行驶」），不说成「固定解中断」。
收到主天线 BESTPOS 标回 `dual`（单天线接收机不要开 BESTPOS，只发 INS.NAVI 和 GGA / GSA / GST 质量语句）。

`line_mission` 看 fix 消息的 `antenna_mode`，变了就 `GnssFusion.switch_config` 换一套配置（`line_node.single_antenna_config`）：
杠杆臂换成右天线，滤波状态、历史、标定统计重来，本地原点和倾斜零点留着；正在作业就停下。单天线接收机的 INS.NAVI 已是它
自己按杆长做完倾斜补偿的坐标（2026-10-07 用户；杆长要在接收机上设成天线离地高度，不设等于没补），单天线配置关掉车端倾斜
补偿（`tilt_compensation_enabled = False`，状态 `tilt.reason = receiver`，坡度开关挡住），免得补两次。没有测向，车头 = IMU 航向角 + 偏移，偏移按卫星位移修
（`_imu_course`，`course_align_distance_m > 0` 时走它，2026-10-07 用户：「用 imu 的航向角做航向，偏移来修正」）：一段里按融合
车头（还没定时是 IMU 航向角加任意偏移）和轮程逐帧推算后轴位移、加上杠杆臂随车头转的那点，就是推算的天线位移；它和这段卫星
测到的天线位移只差一个整体转角，就是偏移的误差（轮径比例只影响长短）。车身摆、弯道、原地转都由 IMU 记着，不要求走直：
还没定车头时走 `course_init_distance_m`（0.5 m）定第一次，之后每走 `course_align_distance_m`（1 m）修一次；来回走、原地转为主
（位移不到要求的一半）不算，已定车头后一段算出超过 `ALIGN_MAX_DEG`（10°，打滑、卫星跳）不修；夹角的不确定度按两端卫星
位置相对误差（每端至少 `ALIGN_FIX_SIGMA_M` 3 mm）。原来按「走直」的轨迹回归（`_position_course`，0.15°/s 走直门槛）定，
全链路仿真里实车拟合底盘低速车身摆 ±1–4°/s，一次也定不出、作业中途也修不上。航向没定之前推算不知道车往哪走，固定解直接定
位置（不判离群）；第一次定出车头时位置按这帧固定解对齐。单天线估不了 IMU 航向角的漂移速度，`bias_initial_sigma_deg_s` 给
0.01°/s（实测量级），不按双天线的 0.2°/s（否则车头不确定度每秒涨 0.2°，起步就超门槛停车）。没有卫星地速，停稳只看轮子
（`ground_speed_still = False`，位姿 `gnss_still_required` 为 false，`robot_core.standstill` 只要霍尔静止；用户：「只要轮子
不动就行」）。起步「往前动一下」由 `line_mission` 的 ORIENTING 阶段做（0.25 m/s 直走）。单天线时 `heading_unavailable` /
`gyro_only` 一直在，按降级限速（`gnss_hold_speed_mps`，直线、圆弧按设定速度的段除外）。

## 卫星定位的固定延迟：在线估计后扣掉（2026-10-07）

用户：「关键是我现在不是主靠 imu 走吗，对卫星的数据要求要这么高？」「好的修复」。横向（线直不直、离线多远）主要由 IMU 保持方向，
卫星延迟几乎不影响；沿线方向（什么时候开喷、停喷、到拐角）只有卫星给绝对位置：定位比标的时间晚 τ，车就以为自己落后
「车速 × τ」，0.8 m/s 每 10 ms 0.8 cm（全链路仿真单天线晚 50 ms：横向 p95 不变，开喷晚 4.3 cm、停喷多 4.2 cm）。车端按接收机的
时间对齐，转发路上的抖动没关系，但固定的那段延迟（接收机内部、平板转发）看不出来——接收机和车没有共用的时钟，
`um982.GnssClock` 只能假设最快到的那帧晚 20 ms。

`gnss_latency.GnssLatencyEstimator`（`line_mission` 喂卫星固定解、轮速、IMU 航向角）：车停着时卫星位置晚多少都一样；每次从停着
（≥ 0.3 s，换向、原地转后的短停也算）起步，这一段（到车又停下、走满 4 m 或 6 s）里卫星测到的天线位置和按轮程 + IMU 航向角推算
的天线位移只差起点、整体转角、轮径比例和时间差 τ，前三个按最小二乘直接解，τ 在 −0.1–0.4 s 里找对得最好的。推算走不到 0.8 m、
车速不到 0.25 m/s、轮径比例差超过 10 % 或对上后残差超过 2 cm 的段不用。取最近 7 段的中位数，**等车停稳了才换上**（车在动时把
卫星时间一下挪几百毫秒，相邻两帧像是跳了「车速 × 差值」，融合按 RTK 抖动变大十几秒不信卫星，仿真里晚 200 ms 时因此停车），
之后卫星数据（定位、副天线、测向、地速）的时间都减去它再交给融合（只往前挪，负的不补）。按天线模式存在 `~/rtk/gnss_latency.json`，
重启、换天线后直接用这一路上次的值。状态 `gnss_latency`（`value_s` 在用的、`pending_s` 等停稳换上的、`recent_s` 最近几段）。

## 当前 Gen5：绝对估计与连续控制输出

`line_node.load_fusion_config()` 为 Gen5 默认开启 `continuous_output=True`。全局滤波仍是四状态
`[x, y, yaw, bias]`：IMU 持续预测转动、轮速持续预测位移，RTK 位置与双天线测向分别校准。
另保存连续的后轴控制输出；控制器使用 `FusedPose.x/y/yaw`，绝对校正按经过的时间逐渐进入它。
旧阿克曼默认不开连续输出，仍直接输出全局滤波状态。

`FusedPose.correction_xy=(global_x-control_x, global_y-control_y)`，
`correction_yaw=wrap(global_yaw-control_yaw)`，分别使用米与弧度。它们是**尚未应用的实际坐标差**，
不是随机标准差。`sigma_xy`、`sigma_yaw` 及 `covariance_xy_yaw` 仍属于全局随机估计，
不能用全局滤波协方差已经缩小来宣称连续输出已对齐。位置差超过 1 mm 或航向差超过 0.05° 时提示
`gnss_alignment`；预算连小于提示阈值的非零差也计入。

正常固定解的输出位置时间常数为 0.25 s；航向时间常数为 0.20 s，绝对航向校正限速 1°/s。
掉线后接回的沿车头、横向校正各限为 0.04 m/s，直到待应用位置差小于 1 cm 后返回正常时间常数。
大于 0.3 m 的位置矛盾先标记重定位并停车，轮速确认停稳后才能直接对齐连续输出。
常态固定解不统一套 4 cm/s 上限，避免轮速比例误差持续堆积。

5 s 是**可信固定解中断期间的兜底上限**，不是 IMU 可以无条件保证的行驶时间。
喷头误差及停车预算可以更早降速、暂停；固定解恢复后仍检查待应用校正，但不延续旧中断倒计时。
具体预算与恢复许可见下文。离线回放与验证边界见
[2026-10-02 验证记录](../artifacts/imu-gnss-replan-20261002/README.md)。

## 接口与使用边界

保留输入方法与数据类，`FusedPose` 增加带默认值的协方差、推算统计及校准差字段，兼容旧调用方。
配置增加噪声、时效、几何、连续输出和门限参数；`calibration()` 的诊断字段见下文。

```python
from gnss_fusion import GnssFusion, FusionConfig

fusion = GnssFusion(FusionConfig(mount_offset_deg=1.5))
# 有固定作业原点时，在送入任何观测前设置：
fusion.set_origin(31.2304, 121.4737, 12.0)

# 驱动收到相应数据后调用，五种传感器不必一起到达：
# fusion.add_imu(imu_sample)
# fusion.add_wheel(wheel_sample)
# fusion.add_fix(gnss_fix)
# fusion.add_heading(dual_heading)
# fusion.add_velocity(gnss_velocity)

# 控制周期使用同源单调时间：
# pose = fusion.pose(time.monotonic())
# pose is None 或 not pose.usable_for_control 时，控制器暂停运动请求。
# 检查 pose.reasons 中的 position_reset，丢弃上一周期的连续轨迹假设。
```

所有 `t` 均为**测量时间**，与本机 `time.monotonic()` 同源。接收机时间换算、GNSS
串口传输延迟及 BESTVEL 自身积分窗口延迟，应由驱动处理，融合层不再减去固定的 80 ms。
BESTVEL 的航迹是天线的运动方向，不能直接理解为车头方向；这一语义及时间标记问题也见
[BESTVEL 官方协议说明](https://docs.novatel.com/OEM7/Content/Logs/BESTVEL.htm)。UM982 解析仍以驱动实现及其设备手册为准。

每个传感器分别维护最后接收的测量时间。重复、时间倒退或已超出历史范围的样本直接丢弃，
不抛异常；跨传感器乱序则回放。非有限的时间、陀螺和轮速值丢弃，无效 GNSS 解不会进入观测更新。
配置错误、未设置原点便调用坐标转换等使用错误会抛 `ValueError`。

`pose(t)` 可查询保留历史内的时刻，或最新测量后至多 0.2 s 的时刻。无初始位置、查询过旧或
超出外推范围时返回 `None`；查询不会推进内部滤波器或累计标定。没有初始化航向时，可返回
`quality='INVALID'`、不可控制的位姿。实例不是线程安全的；多线程 ROS executor 应在适配层串行调用这些方法。

未显式设原点时，采用第一个有效 RTK 固定或浮点解的经纬度和高度。原点是 ANT1 当时的位置，
所以后轴中心初始坐标一般不为零。已送入观测后不要更换原点；需要新原点时暂停控制并新建实例。

## 坐标和航向约定

- 本地坐标：ENU，`x` 东、`y` 北；车体：后轴中心为原点，`x` 前、`y` 左。
- `yaw`：东为 0，逆时针为正，输出范围 `(-π, π]`。角速度、偏航标准差和零偏均使用弧度单位。
- 位置由 ANT1 转为后轴中心：`p_body = p_ant - R(yaw) @ antenna_xy`。填了天线高度时 `antenna_xy` 换成按横滚俯仰
  投到水平面的杠杆臂，见「倾斜补偿」。
- 默认 ANT1 位于 `(0.345, +0.165)` m，ANT1→ANT2 基线车体系角为 `-90°`。

通用航向换算是：

```text
车头 ENU 偏航 = wrap((90° - HEADING) - baseline_yaw_body_deg + mount_offset_deg)
```

按任务第 2.4 节，安装偏差为零时：

| 车头方向 | HEADING | 换算 |
|---|---:|---|
| 正北 | 90° | `(90 - 90) - (-90) = 90°` |
| 正东 | 180° | `(90 - 180) - (-90) = 0°` |
| 正西 | 0° | `(90 - 0) - (-90) = 180°` |
| 正南 | 270° | `(90 - 270) - (-90) = -90°` |

`mount_offset_deg` 是**加到换算结果上的修正量**。例如真实车头朝东、接收机报告
`HEADING=181.5°`，则应配置 `mount_offset_deg=+1.5°`，输出才是 0°。
实现使用基线参数，未把换算写死为 `180° - HEADING`。

坐标转换先用 WGS84 椭球计算 ECEF，再旋转到原点的 ENU 切平面，不使用等距经纬度近似。
二维接口没有高度参数，故 `to_local(lat, lon)` 把输入置于**原点椭球高**；逆变换沿原点
法线求与相同椭球高曲面的交点，而不是令 ENU 的 U 为零。这使 1 km 范围内的二维接口互逆。
这与标准 [ECEF→ENU 操作](https://proj.org/en/stable/operations/conversions/topocentric.html) 的坐标定义一致；
固定高度是本二维接口额外施加的约束。

`GnssFix.height_m` 仅在自动建立原点时使用，`sigma_u` 不参与平面滤波。
测向 `pitch_deg` 用于双天线互检的水平基线投影；高度、滚转和俯仰的天线杆臂补偿见「倾斜补偿」。

## 状态量、滤波和延迟处理

全局状态为 `[x, y, yaw, bias]`，另保存连续输出、最新运动输入、观测时效和标定统计。
`rate` 模式的 bias 是原始陀螺零偏；`angle` 模式是 IMU 内算航向角的漂移率，两者不能混用。
接口仍保留 `gyro_bias` 字段名，诊断 `heading_filter.bias_kind` 区分 `gyro_bias` / `angle_drift`。
维护完整 4×4 对称协方差，代码展开其上三角十项，避免小矩阵分配占用延迟回放的大部分时间。

预测使用有符号轮速和扣除零偏的陀螺。恒定角速度区间用圆弧积分，接近零角速度时连续退化为直线。
新陀螺到达后回放前一个 IMU 间隔，在线性插值的角速度上积分，减少转弯起止处一整帧的相位滞后。
输入超过时效后不无限保持旧值；角度不确定性继续增长。轮速过期禁止控制；Gen5 IMU 失效时
可用差速轮速预测转动，可信双天线仍能校准航向，不能仅因 IMU 失效就停用 GNSS。

双天线航向对 `yaw` 做标量卡尔曼更新，通过相关协方差估计慢漂；Gen5 转弯、重接时冻结漂移学习。
观测标准差采用接收机报告，最低 0.1°；航向新息先环绕至 `(-π, π]`，再做 5σ 检验。
Gen5 对相关观测与修正增益另做限制；超门限恢复检查连续卫星质量、运动或合格航迹等证据，见下一节。
仅以下情况可用：`L1_INT`、`NARROW_INT`、`WIDE_INT`，卫星数足够、各字段有限。
通用配置不写死天线间距；Gen5 融合另启用 0.40–0.43 m 的测向长度带。`rtk_node` 在两根天线都是 RTK 固定解时按两者平面坐标
（东、北）的实时距离核对测向，结论写在 `/gnss/raw` 测向消息的 `valid` 里（距离不足 0.10 m 视为室内转发器，
不算）；`line_node` 只把 `valid` 为真的测向交给融合。

位置过程噪声分方向：沿车头 `position_walk_m_sqrt_s`（轮速比例误差、打滑），垂直车头只有
`cross_walk_m_sqrt_s + cross_walk_turn·|角速度|`。车不会横着走，直行时轮速+陀螺推算的侧向位置在几秒内
采用较小的侧向预测噪声，所以 RTK 的侧向短时跳动只被慢慢吸收；这是假设轮胎不侧滑的模型，不是毫米级精度保证。
转弯时轮胎会侧滑，侧向噪声随角速度放大。轮速或陀螺
中断时退回各向同性。（实车 2026-09-26：固定解 1 s 内侧移 8 cm 又跳回，接收机报的精度一直 1 cm，
旧的各向同性模型跟着偏了 8 cm，控制器按假偏差纠偏，车真的偏出 3 cm。）

GNSS 位置的观测模型为 `p_ant = [x, y] + R(yaw) @ antenna_xy`（填了天线高度时换成按姿态投到水平面的杠杆臂），雅可比包含杆臂对航向的导数。
先做二维新息检验，再逐轴更新。位置采用 Schmidt 更新：更新位置及交叉协方差，保留航向和
零偏的估计及其协方差子块。因此在航向和有效航迹都缺失时，位置观测不会暗中把航向标准差压小；
这时确实由陀螺推算航向。

`rate` 模式在轮速绝对值不超过 2 mm/s、持续至少 1 s、输入仍新鲜时，将静止陀螺作为零偏观测；
差速车还必须确认没有原地转动。`angle` 模式不拿单帧量化角增量估静止零偏。

尖峰判据为：

```text
abs(gyro_z - bias) <= abs(speed * wheel_scale) * tan(max_steer_rad) / wheelbase_m
                      + radians(gyro_margin_deg_s)
```

这是保守的阿克曼上限，未减去轮距带来的曲率限制，因此允许真实满舵快速转向。
被拒绝的样本保留上一有效角速度，也不参与零偏更新和插值；静止的 -3.8°/s 单点会被排除。
航向角参考时间仍更新以便下一帧接续增量，但 `imu_valid_t` 只由有效运动输入更新。
重复坏帧不能刷新 IMU 有效性、压低缺失期间的不确定度或阻止有效 GNSS 接管。
轮速过期时不凭陈旧轮速限制陀螺，而是通过 `wheel_stale` 禁止控制。

历史默认保留 1 s、最多 256 个样本及其完整状态快照，以先达到的上限为准。
相同时间戳按轮速、IMU、航向、位置、速度排序，延迟观测插入后从受影响的快照回放到现在。
状态快照包括连续输出、待接回状态、航向冲突、标定回归、计数、静止计时和重置状态，不会因回放重复累计。
位置与航向使用的双天线互检证据随各观测存入事件；回放不读取随后改变的实时互检状态，也不使用测量时刻之后的证据。
轮速晚于 IMU 时也回放相关积分区间。运算量和存储量由窗口限制，不随运行时长增长。

## Gen5：航向推算用 IMU 航向角（2026-09-28）

Gen5（`drive_differential`）上，`line_node` 默认设 `yaw_input='angle'`：两次测向之间转了多少，按 HDA536T 自己算的航向角的增量算，不再积分陀螺 z 轴角速度。旧车仍是 `'rate'`。`fusion.json` 里写了这些键就以文件为准。

- **绝对参考由可信测向提供**：IMU 航向角上电为 0；其增量持续预测，双天线长期校准参考偏移及慢漂。
  IMU 也在有效测向期间工作，漂移状态不等于原始陀螺零偏。
- **怎么算**：
  - 相邻两帧航向角之差 ÷ 时间差，作为这一段的转速。积分结果正好等于 IMU 航向角的变化，过 ±180° 自动回绕。
  - 这一帧没带姿态时，退回用陀螺。
- **尖峰**：差速车航向角模式的合理角速度至少放宽到 `angle_rate_floor_deg_s=150°/s`，再留余量，
  避免低速时轮速角速度偏小而拒绝真实转动；另放宽一个分辨率（0.01°）÷ 帧间隔。
  - 2026-10-03 由 70 提到 150：原地转起步驱动器冲过头，车身实际 81°/s，轮速读数落后，70°/s 把真实转动当尖峰丢了。
  - 航向清零、传感器重启引起的跳变当尖峰丢掉，下一帧从新的角度接着算差。
- **静止零偏**：航向角 0.01° 一格，单帧的差不能当零偏观测，所以航向角模式不做静止零偏观测，漂移由双天线测向估。
- **数据来源**：`line_node` 从 `/imu/data` 取航向角（四元数的偏航）和陀螺交给融合，`/imu` 不进融合，同一帧不送两遍。

原地转向的两项误差模型（Gen5 默认打开，旧车为 0）：

- `yaw_scale_sigma = 0.03`：转过的角度按 3% 的刻度误差加大航向不确定度。
  - 2026-10-02 按整段相关累计转角增加方差，测向更新后按实际增益逐渐减小该累计量；同一转弯不会因事件切分更密而变得虚假精确。
  - 不加的话，原地转 90° 后滤波器自认航向 σ 约 0.02°，会把比它偏 0.5° 以上的正确测向当离群值一直拒掉，航向错着还「可控」。
  - 旧版仿真记录：刻度误差 3% 时，转完约 0.3 s 回到 0.05° 以内；不加时一直偏 2.5°。这不是当前连续控制输出的恢复时长。
  - HDA536T 慢慢画圆时刻度很准（空旷处 3 圈 1078°，与双天线测向只差 0.4°，0.04%），原地转（0.8 rad/s）却不是：
    2026-10-01 测向可信的 6 次原地转，IMU 与测向差 0.05%–1.3%（最多 2.2°）。同日曾改成 0.5%（随「IMU 权重加大」），
    转完要 1–2 s 才跟回测向：转完 0–2 s 融合航向与测向之差 p95 矩形 0.33 → 0.59°、另一次 0.55 → 1.78°；
    仿真刻度差 3% 时把 19 帧正确的测向拒掉、转完还偏 2.2°。当天改回 3%（0.45 / 0.67°），直走的抖动照样少。
- `heading_sync_s = 0.02`：测向误差再加「角速度 × 20 ms」，转得快时少信测向，因为时间同步误差在转向中影响最大。

## Gen5 航向：卫星确定绝对基准，IMU 补充短时转动（2026-10-04）

稳定本身不能证明测向正确。Gen5 不采用“连续被拒 0.5 s、测向稳定就直接重定”的规则，
使用 `heading_disagreement` 说明测向与运动证据冲突。位置与航向分开判断：位置可信但测向无效时仍用位置；
位置互检异常也不直接推定测向错误。`recent_dev` 当前只对 RTK **位置**降权，未连续调整航向方差；
互检通过不能单独证明亚度级测向正确。

- **观测方差**：报告精度下限 0.1°，转动时增加同步误差；按 `heading_correlation_s=0.25 s` 放大相邻相关观测的方差，避免 20 Hz 测向被当成同样多的独立证据。
- **慢校与快校**：通过放大观测方差限制 KF 航向增益 `K ≤ 1-exp(-dt/tau)`，保持均值与协方差更新一致。
  直行 `heading_straight_tau_s=2.0 s`；明显转弯、转后约 1 s、证据支持的恢复或 IMU 失效时使用 `heading_turn_tau_s=0.15 s`。
  转弯判据独立使用 `heading_turn_rate_deg_s=3°/s`，不复用航迹标定的 0.15°/s 门限。连续输出随后仍执行自身航向平滑与 1°/s 校正限速。
- **冲突与恢复**：测向突然阶跃却没有对应 IMU 转角时冻结该来源。新增独立于旧绝对航向的恢复窗口：
  连续 1 s、至少 10 帧 `NARROW_INT` 测向，报告标准差不超过 1°，通过配置的基线长度检查；
  同时主天线固定解新鲜、双天线位置互检为 `ok` 且偏差不超过 `dual_ok_m`，位置没有被隔离，IMU 与轮速新鲜。
  行驶中扣除该窗口内 IMU 的转动增量后比较测向稳定性，不拿旧累计航向作恢复前提；
  窗口内角度极差不超过 `max(0.5°, 1.5 × 最大报告标准差)`。无效帧、质量不合格、间隔超过 0.2 s
  （或更短的 `heading_timeout_s`）和不稳定测向中断窗口。
  通过后允许卫星纠正旧推算，无需先自行回到 0.3°以内；通过协方差一致的更新和平滑输出接回，禁止角度硬跳。
  新恢复及其后 1 s 使用快校时间常数；卫星数量达到 38 或更多也不会绕过这些质量条件。
  原来的合格 RTK 位移航迹和 IMU 确实失效接管继续有效。转弯本身不作为大新息的放行依据；
  遮挡中夹杂的异常测向不能仅凭“正在转弯”进入快校、突然放大航向方差并中断 IMU 维持。
- **开始与继续**：直线、路线、场地作业、补画、人工继续和自动继续都要求新鲜可用的卫星航向，
  `heading_unavailable`、`gyro_only`、`gyro_hold`、`baseline_off`、`heading_disagreement` 等状态不能作为起步依据。
  申请控制权后、真正下发第一条运动指令前再检查一次；无效原始测向立即撤销旧测向许可。
  双天线恢复后仍等待位置/连续输出校正和原有起步条件满足。起步并不停止 IMU 传播，
  它继续补充两帧卫星测向之间的转动；只有已在行驶的任务才允许临时 `gyro_hold` 放宽。
- **漂移学习**：只有 IMU 有效、非转弯、残差小、连续输出航向已对齐，且超过恢复冻结窗口的持续测向才更新漂移率。
  Gen5 RTK 航迹与 BESTVEL 只校准角度，不学习 bias；转弯误差、初始角度偏差和角度重接不能学成伪漂移率。
  Gen5 额外航向游走仍为 `yaw_walk_deg_sqrt_s=0.03°/√s`，不能将其单独换算成固定的测向接管时间。
- **IMU 断了**（`imu_stale`）：
  - 差速车改用轮速里程计的角速度推两次测向之间的转动，原地转时也有；
  - 双天线有效时仍更新绝对航向；是否能开同时取决于随机不确定度、待校准差和任务预算；
  - 测向也没有时不可控。反复被拒绝的 IMU 尖峰按有效输入时间判断失效，不算新鲜运动证据。
- **IMU 与轮速里程计相反**（`imu_mismatch`，差速车，两种推算模式都查）：
  - 判据：两边都明显在转（轮速角速度 ≥ 0.2 rad/s，IMU ≥ 0.1 rad/s），方向持续相反 0.2 s。
  - 判出后到重启都不再用 IMU；放大航向不确定度，可信测向逐步收敛，之后同 IMU 断了。
- **航向门槛**：刚接受过测向时全局随机航向 σ 可放宽到 2°（`HEADING_HOLD_SIGMA_DEG`）；没有测向时仍为 0.5°。
  待校准差另进入喷头预算，不能只凭这项随机 σ 放宽控制许可。
- **测试**：`tests/test_imu_yaw_fusion.py`、`tests/test_fusion_quality_regression.py`。

旧阿克曼兼容路径仍保留 `REANCHOR_S=0.5 s`、测向跨度不超过 0.5°、低于 3°/s 时的硬重定，
并提示 `heading_reset`。这是旧车规则，不能用它描述当前 Gen5。

## 卫星质量、喷头预算与连续输出恢复（2026-10-02）

Gen5 新增任务层推算误差预算（`radar_system/rtk_hold_budget.py`）：`line_node` 默认开启 `hold_budget_enabled`。
5 秒仅为可信固定解中断时的绝对上限（2026-10-02 由 8 秒调整）；控制还检查喷头当前误差及下发停车后停稳时的预计误差，可能更早停车。
固定解 0.5 秒没更新（`hold_watch_s`）才进入完整中断预算，并按 `rtk_hold` 状态报告；此前的短时转发间隔不按持续中断处理。2026-10-04 用户指定门槛为 500 ms。

- 融合位姿附带同一历史快照的 x/y/yaw 协方差、最后固定解后的绝对路程和转角。查询/延迟回放不重复累计，倒车不抵消路程。
- 将全局协方差通过**全局航向**处的喷头杠杆臂 `J P Jᵀ` 换算，再投影到当前路径横向/沿线方向。
  待校准差使用实际前伸、右偏杆臂 `lever` 的精确旋转差：

  ```text
  pending_nozzle = correction_xy + (R(global_yaw) - R(control_yaw)) @ lever
  ```

  分别将其横向、沿线投影的绝对值加进预算；停车距离另加 `abs(sin(correction_yaw))` 引起的横向余量，
  并计沿线方向变化。路线只提供误差方向，不吸附或校正位置。
- 估计预算为 `hold_sigma_multiplier` 倍随机标准差，加轮速比例、滑移和转角刻度余量。候选初值：横向 3 cm、沿线 10 cm，标准差倍数 2；轮速比例余量 2%，滑移 1 mm/s 加路程的 0.2%，转动另加 1 cm/rad，转角刻度余量 3%。这些是保守模型初值，须通过实车回放/独立测量标定，不能称为真实误差保证。
- 停车预估覆盖最近已发出指令、速度/转速执行延迟、一个 50 ms 控制周期和减速过程。失联时外推完整随机过程、轮速及滑移余量；
  固定解已恢复但仍有校准差时，使用当前随机协方差、待校准差及其停车运动余量，不假设整个制动期间 GNSS 都失联，也不继承旧的 5 s 倒计时。

## 横向精度：测向偏差学习、RTK 观测噪声（2026-10-02）

用户要水泵横偏 1.5 cm 以内，并要求按当前车上算法测。用全链路仿真（车上 `line_node.load_fusion_config` + 本融合 +
`LineMission` 作业；底盘与传感器按 10-02 实车数据校准，17:15 那版代码的主天线直线度、控制器横偏、车身摆动三项与实车对上）
找到的主因：位置只修位置、不修航向（Schmidt 更新），横向过程噪声又很小（`cross_walk_m_sqrt_s` 0.0015，防 RTK 横跳），
航向有一点误差推算就把横向位置带偏，RTK 只能慢慢拉回——测向偏 1° 时 0.8 m/s 水泵整条线约偏 1.1 cm
（实车「RTK − 融合」左向均值同一机理，可以直接读出这个偏移）。水泵与主天线前后对齐，横向位置紧跟 RTK 时
航向误差几乎只影响水泵的前后位置。改了三处，都只在 Gen5（`line_node` 设）：

- `heading_bias_learning`：在线学双天线测向的固定偏差并从测向里扣掉。同一段路上「轮速 × 融合航向推出来的天线位移」
  与「RTK 实测的天线位移」方向之差就是剩下的偏差（与车身摆不摆、是不是直线无关）；天线走够 4 m 比一次，前 6 段增益 0.5、
  之后 0.15，单次最多 0.2°（测向一下子挪 0.75° 以上会被当成测向跳变），总共最多 2°；一段里转过 30°、断了、离群、互检不过、
  降权都重新开始。`calibration()['heading_bias_learned_deg']` 报学到的值。
- `fix_floor_m` 0.002、`fix_sigma_scale` 0.25：RTK 固定解按逐帧抖动（实测约 1 mm）给观测噪声，不按接收机报的绝对精度
  （约 8 mm）。RTK 断了时推算误差怎么涨（`cross_walk_m_sqrt_s` 等，推算维持预算也按它算）不变，照旧维持 5 s。
- `fix_jitter_k` 2：观测 σ 不小于 2 × 实时估的 RTK 抖动（相邻两帧固定解相对推算的跳动，3 s 指数平均），靠楼多路径时
  自动少信 RTK；转动时再加「转速 × 杠杆臂 × `heading_sync_s`」。
- `output_position_tau_s` 0.25 → 0.10：控制输出跟融合状态少 0.15 s 滞后。

全链路仿真，水泵横偏 95%（12 趟中位 / 最差一趟），四种底盘模型结果一致（这里是最像实车的 C）：

| 作业 | 改前 | 改后 |
|---|---|---|
| 直线 0.8 m/s | 1.20 / 2.21 cm | 1.12 / 1.57 cm |
| 直线 0.5 m/s | 0.99 / 1.61 cm | 0.86 / 1.43 cm |
| 矩形 0.8 m/s | 1.57 / 2.22 cm | 1.47 / 1.91 cm |
| A→B 0.8 m/s | 1.38 / 2.19 cm | 1.31 / 1.79 cm |

（共模漂移）两者都分不出来。真实数据回放（`artifacts/imu-gnss-replan-20261002` 的 `bld_open`、`gaps3`）：没有新增重置，

## 倾斜补偿：天线高度 × 横滚俯仰（2026-09-28）

天线装得比地面高。车在横坡或纵坡上，天线的水平位置会偏出去，偏多少是 天线高 × sin(坡度)：

| 天线离地 | 1° | 2° | 3° | 5° |
|---:|---:|---:|---:|---:|
| 0.4 m | 0.7 cm | 1.4 cm | 2.1 cm | 3.5 cm |
| 0.6 m | 1.0 cm | 2.1 cm | 3.1 cm | 5.2 cm |

不补的话，这段偏差全算成车的位置，喷头就画偏了。填了天线高度（`antenna_height_m > 0`）后，融合把 ANT1 的三维杠杆臂
`(antenna_xy, antenna_height_m)` 按 IMU 姿态投到水平面：

```text
R = Rz(航向)·Ry(俯仰)·Rx(横滚)                  ROS REP-103：横滚左侧抬起为正，俯仰车头压低为正
水平杠杆臂 前 = ax·cos(俯仰) + (ay·sin(横滚) + h·cos(横滚))·sin(俯仰)
水平杠杆臂 左 = ay·cos(横滚) − h·sin(横滚)
p_ant = [x, y] + Rz(航向) @ 水平杠杆臂
```

所以融合输出的 `(x, y)` 是后轴中心正下方的地面点，不是天线在地面上的投影。坡上左侧抬起时天线往右偏，车头压低时天线往前偏。
平地（横滚俯仰都为 0）时和原来的 `antenna_xy` 完全一样。

- **姿态从哪来**：`ImuSample.roll` / `pitch`（弧度）。Gen5 是 HDA536T 在 `/imu/data` 里给的姿态（传感器内置卡尔曼、离心加速度已补偿，
  手册动态精度 ±0.1°），和航向角同一帧交给融合；旧车是 `imu_filter_madgwick` 的 `/imu/data`，`line_node` 把 0.1 s 以内的姿态
  带在 `/imu` 陀螺帧上。
- **天线高度怎么量**：车停在平地上，量天线底座到地面的高度，再加天线相位中心高于底座的那段（看天线手册，一般几厘米），写进
  `~/rtk/fusion.json` 的 `antenna_height_m`（米）。高度量错 5 cm，3° 坡上只差 2.6 mm；姿态误差 0.1°、天线高 0.4 m 只差 0.7 mm。
  没量过就保持 0（不补），不要猜。
- **只降级、不停车**（与「航向以双天线为主」同一原则）。下面三种情况退回平地杠杆臂，原因加 `tilt_uncompensated`，照常能开：
  - 0.2 s（`sensor_timeout_s`）没有新姿态：`attitude_stale`；
  - 横滚或俯仰超过 `max_tilt_deg`（15°）：`too_steep`。划线车不会开这么陡，多半是车被抬起或姿态出错；
  - IMU 已判为与轮速里程计相反（`imu_mismatch`）：姿态也不信。
  
  没填天线高度（`no_height`）不算问题，不加原因。
- **状态**：`tilt_status()` → `/line/status` 的 `tilt`：天线高度、在不在补（`active`）、没补的原因、用的横滚俯仰、
  补偿量（天线水平位置比平地时偏了多少，车体系前、左，米）。app 姿态卡片显示。
- **定位跳动核对**：`line_mission` 用 `antenna_lever()` 取同一个杠杆臂，坡上天线偏出去的那段不会记成跳动。
- **没补的**：双天线测向的基线也会随车倾斜，但只影响二阶项（横滚 × 俯仰，3° × 3° 约 0.16°），不补。喷头在地面附近，
  倾斜对它的影响是 cos 项，0.3 m 臂长 3° 不到 0.5 mm，也不补。
- **上车核对**：先按 `rion_protocol/README.md` 第 4 步确认姿态方向（垫高车头显示「车头高」，垫高左侧显示「左侧高」）。
  方向反了补偿会让误差翻倍。
- **测试**：`tests/test_tilt_compensation.py`。和独立写的三维旋转矩阵逐项对照；0.5 m 高天线、横坡 3° 纵坡 1.5° 直行，
  补偿后位置误差 < 3 mm，不补约 2.6 cm；姿态中途断掉照常能开。

## 降级、恢复与控制许可

| 情况 | 行为 |
|---|---|
| `NARROW_INT` 固定解 | 使用报告的东西/南北标准差，最低 5 mm |
| `NARROW_FLOAT` / `L1_FLOAT` / `IONOFREE_FLOAT` | 更新位置，但标准差至少 0.15 m；标为 `RTK_FLOAT` |
| `SINGLE` / `PSRDIFF` / `NONE`、过期差分等 | 不更新位置；标为 `DEAD_RECKONING` |
| 双天线失效 | 连续直行且速度足够时尝试 BESTVEL 或 RTK 位置序列航迹；倒车反转 180° |
| 无双天线及有效航迹 | 仅靠陀螺推算航向，`sigma_yaw` 增长 |
| 固定解恢复、位置新息 ≤5 cm | 常规滤波更新，逐渐收敛 |
| Gen5 固定解恢复、位置新息 >5 cm 且 ≤0.3 m | 全局估计接回，控制输出平滑校准；待应用差进入喷头预算，预算超限先暂停 |
| Gen5 恢复位置矛盾 >0.3 m | 标 `position_reset`，先暂停并确认停稳，再对齐连续输出 |
| 旧车或关闭连续输出，固定解恢复、位置新息 >5 cm | 按旧重置/接回配置处理，可能直接重置并暂停 |
| 正常固定解中出现位置离群值（新息 >`soft_gate_sigma`） | 不丢弃，方差按离群程度放大（Huber）：离得越远影响越小，持续的小偏差几秒内平滑吸收，不会一步跳过去 |
| 固定解连续离群满 `outlier_reset_s` 且位置新息 >5 cm | 按可信度及车型进入恢复/重置路径；Gen5 连续输出仍需计入残差预算，大矛盾先停 |
| 浮点解位置离群值 | 新息门限（5σ）拒绝，不能当作恢复重置 |

BESTVEL 缺少单独的方向标准差字段，默认按 `atan2(0.03 m/s, speed)` 推算航迹噪声。
位置序列用有符号轮程与 RTK 坐标做在线回归，至少覆盖 3 m；降级航向观测至多每秒注入一次，
对重叠窗口噪声加保守下限，避免把相同数据重复当作独立高精度航向。
BESTVEL 的 `sol` 接受常用位置解类型、`DOPPLER_VELOCITY` 或驱动已验证的 `SOL_COMPUTED`；
驱动必须检查原始解状态，不能只转发一个成功状态字符串掩盖无效速度。

融合或任务层遇到下列条件会令控制位姿 `usable_for_control=False`：

- 旧车无推算维持时，0.5 s 没有可信固定解即不可控；Gen5 0.15 s 后先预算、0.5 s 后报告 `rtk_hold`，
  预算/停车时间或 5 s 中断上限不足时暂停（`rtk_hold_budget_exceeded`、`rtk_hold_braking_timeout`、`rtk_hold_timeout` / `rtk_fixed_timeout`）。
  互检判过不可信的恢复样本须重新比过，不能凭最近没有互检就直接接回。迟到数据仍按测量时刻处理，超过 1 s 历史窗直接丢弃。
- 全局最大坐标轴水平 1σ 超过 0.03 m，`position_uncertain`：最近一次固定解后 `rtk_hold_s` 以内（Gen5 9 s，含固定解刚断的头 0.5 s）
  只提示、照常可控；超过才不可控。Gen5 推算维持期间由喷头预算进一步决定控制许可。
- 喷头当前或停车预算超限、数据不足，或未应用校准差使预算超限；固定解恢复后也适用。
- 航向 1σ 超过 0.5°，`heading_uncertain`。双天线测向有效时放宽到 2°。
- 轮速过期，`wheel_stale`。
- IMU 过期（`imu_stale`）或与轮速里程计相反（`imu_mismatch`），**而且**双天线测向无效。测向有效时只提示，不停车。
- 航向尚未初始化，`heading_uninitialized`。
- 位置重置的保持窗口内，`position_reset`。

`heading_unavailable`、`course_heading`、`gyro_only`、`rtk_float`、`tilt_uncompensated`、`heading_reset`、
`rtk_hold`、`rtk_rejoin`、`rtk_weighted`、`baseline_off`、`heading_disagreement`、`gnss_alignment` 等也用于说明来源（app `Narrative.kt` 翻成中文），
单独出现不一定禁止控制；控制器应判断布尔许可，不能把所有 `reasons` 都当成同一等级的故障。
`fix_unavailable` 代表无效位置输入，`position_outlier` 代表位置新息被拒绝。

新息和时效按测量时间检查。位置重置一旦在回放中首次发现，另从当前最新时间保持 0.5 s 的
可见提示；即使重置测量迟到 0.75 s，控制器也不会漏掉跳变。
接口不发布运动指令、不解除急停、不自动恢复任务；这些仍由上层处理。

## 在线标定与室外流程

标定使用**原始双天线换算角**，而非已经加过配置修正的融合航向：

```text
raw_yaw = wrap(90° - HEADING - baseline_yaw_body_deg)
mount_offset = wrap(后轴速度方向 - raw_yaw)
```

直行时对 `(有符号编码器累计距离, RTK东坐标, RTK北坐标)` 做中心化在线线性回归。
斜率方向提供车头方向，斜率模长提供真实距离/编码器距离的比例。倒车时自变量递减，
因此斜率仍指向车头，不会把安装角估成相差 180° 的值。换向、转弯或失锁时结束该段并汇总，
累计量只有固定数量的标量。位置回归不足时，可报告 BESTVEL 的圆均值估计。

两种来源不被当成独立数据重复加权；存在合格 RTK 位置回归时优先使用它。
安装偏差与轮速比例都**只报告、不自动生效**，也不写入磁盘。

建议的人工标定步骤：

1. 在室外开阔、平整、不打滑的地面确认两根天线都是固定解、测向固定。先静止 3～5 s；`rate` 模式估陀螺零偏，`angle` 模式不做单帧静止漂移率观测。
2. 保持方向，约 0.4～0.8 m/s 前进 20 m，避免频繁转向。停车后再在同一直线上倒车一段。
3. 读取 `calibration()`，确认正向与含倒车的数据给出一致的安装角和轮速比例。
4. 检查样本量、95% 区间和数据来源；换一处开阔地重复，排除多路径或地面侧滑造成的系统偏差。
5. 由上层展示结果并经人确认，把 `mount_offset_deg` 与 `wheel_scale` 写入配置；重启融合实例后生效。

`calibration()` 的主要字段：

| 字段 | 解释 |
|---|---|
| `mount_offset_deg` | 待确认的安装角修正；不足时为 `None` |
| `mount_offset_sigma_deg` / `mount_offset_ci95_deg` | 估计标准差 / 95% 区间半宽 |
| `mount_offset_samples` / `segments` | 实际累计的有效航向样本数 / 合格位置回归段数 |
| `mount_offset_confident` | 样本 ≥100 且 95% 半宽 ≤0.2°；仍需人工确认 |
| `mount_offset_source` | `rtk_position`、`bestvel` 或 `None` |
| `applied_mount_offset_deg` | 当前实际使用的配置值 |
| `wheel_scale` | 轮速乘数；报告速度高 2% 时应约为 `1/1.02 = 0.980392` |
| `wheel_scale_sigma` / `wheel_scale_ci95` | 轮速乘数标准差 / 95% 半宽 |
| `wheel_scale_samples` / `wheel_scale_confident` | 回归位置样本数 / 样本 ≥100 且 95% 半宽 ≤0.003 |
| `gyro_bias_deg_s` / `gyro_bias_sigma_deg_s` | 当前 bias 及标准差；`rate` 是陀螺零偏，`angle` 是内算航向漂移率 |
| `heading_filter` | 航向新息、门限比值、实际增益、冲突标记及 `bias_kind` |
| `alignment` | 尚未应用的位置差 `x_m/y_m` 与航向差 `yaw_deg`；不是协方差 |
| `rejected` | 各传感器时间序列丢弃计数、陀螺尖峰、航向离群计数；位置离群计数含固定解降权次数 |
| `position_resets` / `history_samples` | 回放后的位置重置次数 / 当前缓存数量 |

置信区间基于噪声模型和拟合残差，不包含卫星多路径、错误基准、安装松动或长期相关误差，
不能用 `confident=True` 自动覆盖人工配置。`FusedPose.mount_offset` 始终是配置值的弧度表示。

## 测试与已知局限

仓库根目录运行：

```bash
python3 -m pytest tests/test_gnss_fusion.py -q
# 当前 Gen5 的质量、连续输出、预算及恢复回归：
python3 -m pytest tests/test_imu_yaw_fusion.py tests/test_rtk_hold_budget.py tests/test_fusion_quality_regression.py -q
# 查看各验收场景的实测数值：
python3 -m pytest tests/test_gnss_fusion.py -q -s
# 单独运行默认直线仿真：
PYTHONPATH=radar_system python3 radar_system/tools/fusion_sim.py
```

生成器使用种子 20260925，传感器噪声与传输延迟使用独立随机流。标准直线场景先静止
3 s 初始化，再以 0.5 m/s 行驶 40 s（20 m）；运动指标覆盖完整 20 m。偏置 0.1°/s、
陀螺噪声 0.034°/s、量化 0.00026644 rad/s，含 1.3 ms IMU 时间抖动、偶发约 60 ms 间隔和尖峰。
RTK 固定解每轴噪声 1 cm、航向噪声 0.3°、安装偏差 +1.5°、延迟 80±20 ms，轮速含 +2%
比例误差和 1 mm/s 量化。最小转弯半径按现有底盘的 `0.52/tan(0.35) + 0.60/2` 计算。
除安装角标定测试外使用真值 1.5° 配置。另测未经静止预热的运动中零偏估计。

延迟一致性测试重放**同一批实际数值相同的测量**，比较全部到齐后的公共历史和最终位姿，
避免把随机噪声改变混入延迟误差。尚未收到最新 GNSS 的实时输出，不可能与已经拿到该数据的
零延迟滤波器逐时刻完全相同；这项比较不作这种不可因果实现的承诺。

性能计时只包含每次 `add_*`，包含坐标换算、排序、快照和回放，不包含生成测量数据的耗时；
逐传感器检验中位数 <100 µs。一小时测试流式送入约 36 万样本，检查整个融合实例保留对象图
及缓存样本数，允许有界分配波动，不以 Python 内存分配器的 RSS 缓存代替实际保留量。

使用时还应注意：

- 这是离线融合验收，不是实车 2 cm 横向控制的保证；控制周期、转向标定、轮胎侧滑和轨迹跟踪误差另需闭环验证。
- 假设无侧滑。倾斜地面按填的天线高度和 IMU 姿态补偿（见「倾斜补偿」，2026-09-28 加入，只做过仿真）；
  没填天线高度时仍按平地算。车体被抬起或原地外力旋转不在验证范围内。
- 模块按 WGS84 算投影，不承担 CGCS2000/CORS 与 WGS84 的基准转换。驱动和作业坐标必须采用一致的坐标基准和原点。
- IMU 20 Hz 对突变转向有采样限制；在物理上限以内的运动中异常角速度不能一概当作尖峰，否则会误拒真实转向。
- 轮速比例不在线应用；尚有 2% 误差时，2 s、0.5 m/s 的失锁会产生约 2 cm 的沿程误差，不能长期盲行。
- 输入时钟同步误差不能靠重放消除；超出历史窗的数据会丢弃。须在车载 RK3588 上另测最坏延迟及负载，开发机中位数不等于板端实时保证。
- 融合模块本身不导入 ROS；当前仓库已有节点适配与控制接线。本次 2026-10-02 更新仅在本地修改和离线验证，未连接小车或改变其运行服务。
- 本次录包回放保持原始控制命令，没有独立喷头真值；输出数值更连续不等于实车横偏更小。相关结果及版本快照见
  [验证记录](../artifacts/imu-gnss-replan-20261002/README.md)，后续代码修改须重新回放，不能借用早期候选结果。
- 双天线共模漂移可能保持几何一致，不能用互检通过证明绝对位置或航向正确；最终直线精度需要独立测量和闭环实车验证。
