# IMU762 USB 串口接入

协议来源：用户提供的《IMU762 惯性测量模组》，24 页，PDF 创建日期 2026-06-17。
帧格式与校验见第 9–13 页，厂家示例见第 17–18 页。

## 当前接入范围

按用户最新决定，保留模块现状：460800、400 Hz，不再发送频率、波特率或清零命令。
Gen5 的定位节点启动独立接收线程，读取所有完整帧，每个 50 Hz 控制周期只取最新样本。
默认控制来源仍为 HDA536T；App 的「更多 → IMU 选择与对比」可以在停车且无作业时切换。
HDA536T 的原始话题保留，新模块使用 `/imu762/data`，当前选源输出到 `/imu/selected/data`。
详细切换规则见 [IMU_SOURCE_SWITCH.md](IMU_SOURCE_SWITCH.md)。

独立诊断入口仍为 `deployment/run_component.sh imu762`，与定位节点内置接收器不能同时占用同一转换器。
内置接收器只按 USB 元数据匹配唯一的 CH340（1a86:7523），不试开 GNSS 串口。
也可明确设置 `IMU762_PORT` 或 `IMU762_USB_DEVICE`；多个 CH340 时必须指定。
参数设置脚本仍保留为显式诊断工具，正常启动和 App 切换从不调用它。

## 串口与接线

- 默认串口参数：460800 波特率，8 数据位、无奇偶校验、1 停止位，无软硬件流控。
  手册明确给出波特率和 8 bit 数据；8N1 为接收器默认参数，实物若有不同配置需按实际设置。
- 手册出厂输出频率 400 Hz，算法模式 VRU；读取全部接收帧，不在设备上改频率。
- PIN1：VIN；PIN2：GND；PIN3：设备 TXD；PIN4：设备 RXD。
- 手册工作电压为 3.2–6.5 V，典型 3.3 V 或 5 V，PIN1 标为 5 V；不能接车辆 24 V。
- **电平待确认**：PIN3/4 标注 RS232，但同页 IO 表给出的电平是 0–3.3 V。
  接线前应按模块实物型号或厂家说明确认 RS232 与 TTL 的电平，不能仅凭文档标题选择转换器。
- 确认电平后，设备 TXD 接转换器 RXD，GND 共地；只接收时设备 RXD 可不接。

推荐设备名使用 `/dev/serial/by-id/` 下与该 USB 模块对应的路径，避免插拔顺序改变 ttyUSB 编号。
程序需要 Python 3 和 pyserial；ROS 入口另需要现有的 ROS 2 环境。

板子当前内核 6.12.69 未编入 `CONFIG_USB_SERIAL_CH341`。
已确认的 CH340（USB ID `1a86:7523`）可以通过 `ch340_usb.py` 使用已有 libusb 读取，
无需编译内核或加载驱动。该后端只打开指定 USB 设备，不解绑内核驱动，
转换器已有串口驱动时应改用 `/dev/ttyUSB...`。

```bash
python3 rion_protocol/imu762_reader.py \
  --usb-device /sys/bus/usb/devices/实际USB设备名 --baud 460800
```

USB 的 sysfs 名称可能在重新插拔 Type-C 转接器或重启后变化，需按当前 `lsusb` 核对，
不能把本次临时的 `7-1.3` 当成永久设备名。

## 设置为 50 Hz、115200

用户明确要求降低模块输出频率后，可执行以下独立设置脚本。
它先确认完整 IMU762 数据帧，再设置并查询 50 Hz；频率未确认时停止，不继续改变波特率。
波特率按手册没有设置确认回复，发送后接收器切到新波特率，重新查询这两项。
默认写入 Flash，掉电保持；`--volatile` 仅保存到 RAM。

```bash
python3 rion_protocol/imu762_setup.py \
  --usb-device /sys/bus/usb/devices/实际USB设备名 --current-baud 460800
```

50 Hz、约 111 字节/帧在 8N1 下需要约 55.5 kbit/s，选 115200 留出余量。
参数确认成功后，接收命令使用 `--baud 115200`。
设置脚本不改变输出内容、算法模式、安装方向或校准。
读取已经实物确认；本次设置首次执行没有收到任何设置或查询回复，
实际输出仍约 400 Hz。用户已确认发送方向接线、重新上电，重复设置和查询仍无回复；
因此当前按 460800／400 Hz 使用，不把发送成功当成设置生效。

## 终端读取

在板子的发布目录中运行，替换为实际专用串口路径：

```bash
python3 rion_protocol/imu762_reader.py \
  --port /dev/serial/by-id/实际设备名 --baud 460800
```

终端默认每秒最多显示 10 条最新数据，状态每秒写入标准错误。
`--once` 收到一帧有效数据后退出；打开设备失败时退出。
USB 拔出会报告中断，并每秒尝试重新打开同一设备路径。
重连会清掉旧半帧和旧样本，保留累计校验错误统计。

记录全部有效帧：

```bash
python3 rion_protocol/imu762_reader.py \
  --port /dev/serial/by-id/实际设备名 \
  --print-hz 0 --log /root/rtk/imu762/samples.jsonl
```

JSONL 中保存原始帧十六进制、帧序号、全部数据项、未知扩展数据项，
以及主机 Unix/单调时钟接收时间和传感器原始时间戳。
默认每个文件上限 64 MiB，保留 4 个备份，总量约 320 MiB；
用 `--log-mb`、`--log-backups` 调整。没有指定 `--log` 时不创建记录文件。
设备的 32 bit 微秒时间戳是设备时间，约 71.6 分钟会回绕，不当作 Unix 时间使用。
同一次串口读取中的帧可能共享主机接收时间，精细采样时序应使用设备时间戳。

## ROS 独立读取

```bash
export IMU762_PORT=/dev/serial/by-id/实际设备名
export IMU762_BAUD=460800
export IMU762_LOG=/root/rtk/imu762/samples.jsonl
bash deployment/run_component.sh imu762
```

| 话题 | 数据 |
|---|---|
| `/imu762` | `sensor_msgs/Imu`，角速度和同帧加速度，不带姿态 |
| `/imu762/data` | `sensor_msgs/Imu`，含同帧四元数或欧拉角生成的姿态；缺姿态时不发布 |
| `/imu762/magnetic` | `sensor_msgs/MagneticField`，磁场原始强度换为 Tesla |
| `/imu762/samples` | JSON，最新完整样本及原始帧 |
| `/imu762/status` | JSON，连接状态、接收频率、帧龄、校验/长度错误、序号缺口及已收到的数据项 |

ROS 默认最多发布 50 Hz，串口接收与 JSONL 记录仍覆盖全部有效帧。
直接启动接收器时可用 `--publish-hz` 调整到最多 400 Hz。
诊断状态中的接收频率是原始数据频率，不是 ROS 发布频率。
独立入口没有加入车辆自启动组件列表；Gen5 定位节点内置接收器会随定位服务启动。
独立读取脚本已传到板子并读到真实数据；没有切换车辆定位或控制输入。

## 数据解释

- 帧头 `59 53`，序号小端 uint16，数据域长度 uint8。
- 数据域是多组 DATAID、LEN、DATA。未知项按长度保留原始字节；
  已知项长度错误、同帧项重复、半帧和校验错误不会提供给下游。
- CK1、CK2 从序号开始到数据域末尾逐字节累计，各取低八位。
- 加速度、角速度、欧拉角与四元数为小端 int32 × 10⁻⁶；
  磁场强度 int32 × 10⁻³ mGauss；温度 int16 × 0.01 ℃；两个时间戳为 uint32 微秒。
- 欧拉角的字节顺序是**俯仰、横滚、航向**；四元数 q0、q1、q2、q3 按 w、x、y、z 解释，
  与手册第 17–18 页示例的欧拉角对应。
- 按手册文字采用 FRD（前、右、下）坐标系；ROS 数据换成前、左、上，向量 y、z 取反，
  角速度由度/秒换成弧度/秒，四元数换成 x、y、z、w 顺序。
  要求传感器水平安装且 X 轴朝车头；其他安装姿态需要另行设置安装变换。
- 原始值始终保留，四元数明显不合理时不采用；有同帧欧拉角时由它生成姿态。
- 协方差暂按 ROS 的“未知”约定，不套用当前 HDA536T 的精度参数。

实际静止加速度曾读到原始 Z 为正，与手册 FRD 文字约定存在差异；安装后的角度、陀螺正负方向仍需静态核对。
两路对比显示采用 ROS 转换后的角度；切换来源不会发送传感器校准、安装变换或参数设置命令。
