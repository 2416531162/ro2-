# CAN 短时拥堵与换向停稳修复（2026-10-05）

依据当前发布 `4bece3c536ed3a7e`、提交 `7f9f48e` 的最新实车记录。10 个路线任务的 18 个片段中，6 个因 CAN ENOBUFS 进入 FAULT，3 个因换向等待停稳超时中止。

## CAN

SocketCAN 对 ENOBUFS/EAGAIN/EWOULDBLOCK 仅重试同一帧，间隔最多 0.5ms、总期限 4ms；不建立软件队列，不重发已经成功的帧。超过期限仍抛原错误，沿用故障停车/显式复位流程，ENETDOWN/ENODEV/EIO 等真正链路错误立即上抛。正常发送顺序、频率、请求项和内核队列不变。`/oid/status` 新增当前链路实例的重试/超时计数。

与昨晚 `56b0d31` 对比，今日轮速更新没有改变 CAN 发包数量、频率、顺序及原异常处理；同线程轮程计算发生变化，因此尚不能排除节拍的间接影响。旧本地 35 个片段无 IO 错误，今日 6 次错误是真实回归线索，但不能据此断言硬件损坏，也不能宣称已确定最终拥堵成因。

## 停稳

底盘遥测和导航轮程统一调用 WheelMotionAligner.stationary。静止格边往返允许快速 0.6s 有界窗口及原有较慢的往返窗口；必须发生方向反转且位移跨度不超过 1.25 格，单向慢爬不能按格边抖动处理。新鲜回读速度超过 0.06m/s 或计数/回读过期时不能确认停稳。霍尔速度数值和计程算法不变，不通过把低速强制清零解决等待。

多普勒地速独立参与停稳判断，不再因为 RTK 位置被双天线互检降权而停止刷新。保留地速运动学校验、固定解新鲜度、地速 0.35s 过期、地速不超过 0.02m/s、角速不超过 0.05rad/s 等条件。换向仍要求连续 0.3s 停稳，超时仍为 5s。

控制追踪增加 motion_evidence/hall_still/gnss_still（未知明确记 null），方便直接定位下次拒绝原因。
